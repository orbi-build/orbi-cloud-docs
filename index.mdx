Orbi Cloud is the hosted version of Orbi’s **software dark factory**: you define the goal and acceptance criteria, and Orbi takes a GitHub Issue through implementation, tests, independent review, fixes, and merge. Orbi operates the infrastructure.

After you connect a repository, Orbi reads it and suggests work it can do. Review a new task’s draft before handing it off, or dispatch an existing Issue with **Let Orbi do this**. You can also **Write a request** yourself or label an Issue `ai-ready` in GitHub. Orbi delivers the work in an isolated workspace and merges the exact reviewed commit. Issues, pull requests and release evidence stay in your repository.

Orbi Cloud runs the same delivery engine as self-hosted [Orbi](https://orbi.build/?ref=cloud-docs-index), which is open source. The difference is who operates the runner: with Cloud, Orbi does.

## The whole path, end to end

Authorize and connect a repository, choose the work, and decide when to release. Preparing the environment and reading for suggestions start automatically. Once you hand off a task, Orbi takes it through development and merge.

```mermaid

  subgraph setup["Setup — once"]
    direction LR
    s1["1 Sign in<br/>with GitHub"] --> s2["2 Install the<br/>GitHub App"] --> s3["3 Connect a<br/>repository"] --> s4["4 Prepare work<br/>environment, 10–20 sec"] --> s5["Read repository<br/>suggestions, ~2 min"]
  end

  subgraph work["Per task — you choose, Orbi delivers"]
    direction LR
    w1["5 You hand off an<br/>Issue ai-ready"] -.-> w2["Orbi codes<br/>ai-in-progress"] --> w3["PR opened<br/>ai-pr-opened"] --> w4{"Independent<br/>review"}
    w4 -->|clean| w5["Merged<br/>ai-merged"]
    w4 -->|finding| w6["Repair<br/>ai-fix-needed"] --> w3
    w4 -->|unsafe to fix| w7["Stops for you<br/>ai-blocked"]
  end

  subgraph rel["Release — only when you say so"]
    direction LR
    r1["6 You start a<br/>release"] -.-> r2["Gates, CI wait,<br/>bump, tag"] --> r3["GitHub Release<br/>milestone closed"]
  end

  setup --> work --> rel
```

You decide which task starts and when to release. The handoff buttons apply `ai-ready` for you; reading the repository or opening a suggested draft does not dispatch work.

The status page walks you through the same path. Its **Setup progress** list marks the step waiting on you. Release is optional; the last step shows the free allowance on Free, so subscribing is not required for your first delivery.

## The delivery loop

```mermaid
flowchart LR
  issue["Issue labelled<br/>ai-ready"] --> claim["ai-in-progress<br/>(claimed, coding)"]
  claim --> pr["ai-pr-opened<br/>(PR opened + verified)"]
  pr --> review{"Independent<br/>review"}
  review -->|clean| merged["ai-merged<br/>(terminal)"]
  review -->|finding| fix["ai-fix-needed<br/>(repair, then re-review)"]
  fix --> pr
  review -->|cannot be fixed safely| blocked["ai-blocked<br/>(you decide)"]
```

The review is a separate session that did not write the code. It repairs the findings it can and re-runs the tests; only a clean verdict reaches the merge gate. When automatic recovery is not safe, the Issue lands on `ai-blocked` with a comment saying why — that state is a deliberate stop, waiting for a human decision, not a crash.

Read [the delivery lifecycle](/delivery-lifecycle) for what each label means and what moves an Issue between them.

## What it costs

Your first **3 merged deliveries are free** — no card and no subscription. Failed deliveries do not use up that allowance.

After that there are two paid plans, **Solo** and **Pro**. Both include model usage in the price: Solo with 400,000,000 tokens a month and one repository, Pro with 1,200,000,000 tokens a month and up to five repositories. There is no per-token overage billing: when the month's allowance runs out, new deliveries pause until the next month, or until you add your own model key.

The current prices, the yearly option and any founding offer are on the [pricing page](https://orbi.build/cloud/?ref=cloud-docs-index). [Billing](/billing) covers how subscribing works, and [limits and quotas](/limits-and-quotas) covers how the allowance is counted.

## What Orbi Cloud does not do

It does not discover repositories on its own — it only ever works in the repositories you connect. It does not start a release on its own; the release Issue carries the `ai-release` label, which only a human can set. It does not push to your protected branches outside of the reviewed merge, and it does not touch a delivery that is already running when the platform is upgraded.

Read [security](/security) for the full boundary list, including where your model key is stored and what the runner can reach.
