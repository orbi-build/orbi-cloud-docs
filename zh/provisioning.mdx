准备工作环境是搭起你的任务所运行的隔离环境，你一连接仓库它就自动开始。

它不用你触发，你也没法让它更快。一般需要**几分钟**，跑的过程中页面会自己刷新，开着不用管就行。

## 准备期间发生了什么

Orbi 创建一个专属于你这个仓库的环境，把仓库克隆进去，装上交付引擎，然后针对你的仓库跑一遍引擎的 setup 步骤。在你仓库的标签列表里创建 `ai-*` 标签的就是这个 setup：`ai-ready`、`ai-in-progress`、`ai-pr-opened`、`ai-fix-needed`、`ai-merged`、`ai-blocked` 以及其余几个。

setup 是声明式的：缺的标签会被创建，漂移了的会被纠回来，任何东西都不会被删。你自己的标签（`bug`、`enhancement`，不管你用什么）一概不碰。

每个环境严格对应一个租户和一个仓库。环境之间在操作系统层面相互隔离。

## 怎么看进度

准备进行时，状态页的标题是「Orbi 正在准备工作环境」，「开通进度」列表里的「准备工作环境」一步标着「Orbi 处理中」和「约几分钟」。完成后这一步会变成「✓ 已完成」。

同样的状态也按仓库列在状态页「用量与设置」→「已连接的项目」表的「准备状态」那一列：

| 你看到的 | 意思 |
|---|---|
| 「正在准备」 | 在跑。一般几分钟，完成后页面自动更新 |
| 「已就绪」 | 完成。你可以[写第一个需求](/zh/write-a-requirement)了 |
| 「准备失败」 | 停了。这一格会写明原因、时间、出错编号和下一步 |
| — | 从来没开始准备过，通常是因为还没连接任何仓库 |

### AI 模型服务暂时不可用时

如果 Orbi 的 AI 模型服务暂时不可用，而你也没有设置自己的 API key，仓库照样能连上，但工作环境不会开始准备。连接后的页面标题是「仓库已连接，等待 AI 模型服务恢复」。稍后点「继续准备」就行，不会多连一个仓库；也可以点「使用自己的 API key」，用自己的 AI 服务先开始，费用由你的 AI 服务商收取。

## 准备失败时

失败从来不是死路。状态页的「下一步」卡片会写「工作环境准备失败：」，并告诉你处在三种情况里的哪一种；点「查看原因与处理方法」会跳到「已连接的项目」表里那一格，看原因和下一步。

| 状态页标题 | 该谁动手 |
|---|---|
| 「Orbi 卡住了，需要你看一下」 | 你。原因在你这边，下一步会写明要改什么 |
| 「工作环境准备失败，Orbi 会自动重试」 | 暂时谁都不用，Orbi 会自己重试 |
| 「工作环境准备失败（Orbi 这边的问题）」 | 我们。你不用做什么，过一会儿回来看 |

状态页项目概览里，这个项目那一行也会带上同样的区分：「需要你」、「自动重试中」或「Orbi 这边的问题」。

这些标题背后的原因分四类。

### GitHub App 的安装或授权已失效

原因写的是「Orbi 的 GitHub App 安装或授权已失效」。Orbi 没法再为你的安装签出 token 了，通常是因为 App 被卸载了，或者它对这个仓库的访问权限被去掉了。

**怎么办**：点下一步里的「重新授权 GitHub App」，重新安装或重新授权，再回到状态页查看。

### API key 没有被接受

原因写的是「API key 未被接受」。你自己的 API key 被 AI 服务商拒了。

**怎么办**：从账户菜单打开「AI 模型设置」，把 key 改对，详见[模型配置](/zh/model-configuration)。保存后会自动重试，你不需要重新连接仓库。

### AI 模型服务连不上

原因写的是「无法连接 AI 模型服务（API key 或 baseUrl 可能有误）」。key 或者 baseUrl 可能是错的，或者服务商不可达。

**怎么办**：在「AI 模型设置」里检查 baseUrl 和 key，保存前先点「测试连接」。同上，保存后会自动重试。

### 平台一侧的故障

凡是不能归因到你的安装或你的 AI 模型设置的，都是我们这边的问题，例如「工作环境准备失败（Orbi 这边的问题）」或「工作环境配置同步失败」。

**怎么办**：什么都不用做。下一步会写「这是 Orbi 这边的问题，不用你操作。」，或者「会自动重试，不用你操作。」。如果过了一段时间还没恢复，[联系我们](/zh/troubleshooting)。失败详情里带一个出错编号，能定位到你这一次具体的准备尝试，联系时把它一起报上来。

## 重试

准备会自动重试有限的次数。还会重试时，下一步写「会自动重试，不用你操作。」。

如果原因在你这边，把原因修掉就会再试一次：保存一份改对了的 AI 模型设置，即使自动重试的次数已经用完也会重试。如果原因在平台一侧，次数用完后由我们处理，不需要你做任何事。

## 准备完成之后

不需要再做别的。环境会一直保留，两次任务之间你不用重新准备。[写第一个需求](/zh/write-a-requirement)。

再连接一个仓库，会为它准备一个新环境；断开一个仓库，会回收它的环境。
