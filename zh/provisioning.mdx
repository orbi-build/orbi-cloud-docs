开通是搭起你的交付所运行的隔离环境，你一连接仓库它就自动开始。

它不用你触发，你也没法让它更快。正常需要**一到两分钟**，跑的过程中页面会自己刷新，开着不用管就行。

## 开通期间发生了什么

Orbi 创建一个专属于你这个仓库的环境，把仓库克隆进去，装上交付引擎，然后针对你的仓库跑一遍引擎的 setup 步骤。在你仓库的标签列表里创建 `ai-*` 标签的就是这个 setup：`ai-ready`、`ai-in-progress`、`ai-pr-opened`、`ai-fix-needed`、`ai-merged`、`ai-blocked` 以及其余几个。

setup 是声明式的：缺的标签会被创建，漂移了的会被纠回来，任何东西都不会被删。你自己的标签（`bug`、`enhancement`，不管你用什么）一概不碰。

每个环境严格对应一个租户和一个仓库。环境之间在操作系统层面相互隔离。

## 怎么看进度

开通进行时，状态页上的 **下一步** 卡片会显示 **Orbi 正在准备运行环境**，**开通进度** 列表里的 **开通环境** 一步标着 **约 2 分钟**。完成后这一步会变成 **✓ 已完成**。

同样的状态也按仓库列在 **设置与参考 → 绑定的仓库** 的 **开通状态** 那一列：

| 你看到的 | 意思 |
|---|---|
| **正在开通** | 在跑。通常一到两分钟；页面会自己刷新 |
| **开通成功** | 完成。你可以[把第一张 Issue 交给 Orbi](/zh/first-issue) 了 |
| **开通失败** | 停了。这一行会写明原因、发生时间、request id 和下一步 |
| **—** | 开通从来没被触发过，通常是因为还没连接任何仓库 |

## 开通失败时

失败从来不是死路。**下一步** 卡片会告诉你处在三种情况里的哪一种，点 **查看失败原因与修复步骤** 可以看详情。

  <img src="/images/zh/status-provision-failed.png" alt="一次失败的开通，平台正在自动恢复" />
</Frame>

| 标题 | 该谁动手 |
|---|---|
| **Orbi 卡住了，需要你看一下** | 你。原因在你这边，修复步骤会写明要改什么 |
| **开通失败，平台会自动重试** | 暂时谁都不用，Orbi 会自己重试 |
| **开通失败，平台正在自动恢复** | 我们。你不用做什么，过一会儿回来看 |

有多个仓库时，同样的区分会以标记的形式出现在仓库那一行上：**需要你**、**自动重试中** 或 **平台恢复中**。

这些标题背后的原因分四类。

### GitHub App 的安装或授权已失效

Orbi 没法再为你的安装签出 token 了，通常是因为 App 被卸载了，或者它对这个仓库的访问权限被去掉了。

**怎么办**：重新安装或重新授权 GitHub App，然后重试。修复步骤里有指向连接页的链接。

### 模型凭据没有被接受

你自己的模型 key 被 provider 拒了。

**怎么办**：从账户菜单打开 **模型配置**，把 key 改对，详见[模型配置](/zh/model-configuration)。保存新配置会自动重试开通，你不需要重新连接仓库。

### 模型服务连不上

key 或者 base URL 看起来是错的，或者 provider 不可达。

**怎么办**：在 **模型配置** 里检查 base URL 和 key，保存前先点 **测试连接**。同上，保存会自动重试开通。

### 平台一侧的故障

凡是不能归因到你的安装或你的模型配置的，都是我们这边的问题。

**怎么办**：什么都不用做。平台会自动恢复，页面上也会这么写。如果过了一段时间还没恢复，[联系我们](/zh/troubleshooting)。失败详情里带一个 **request id**，能定位到你这一次具体的开通尝试，联系时把它一起报上来。

## 重试

开通会自动重试有限的次数。详情会告诉你处在哪种情况：要么 **开通会自动重试**，要么 **自动重试次数已用完**。

如果是你这边的原因导致重试用完，把原因修掉就会重新开始重试：保存一份改对了的模型配置，即使次数已经用完也会再试一次。如果是平台一侧的原因导致用完，平台恢复会接手，不需要你做任何事。

## 开通成功之后

不需要再做别的。环境会保持开通状态，两次交付之间你不用重新开通。[把第一张 Issue 交给 Orbi](/zh/first-issue)。

再连接一个仓库，会为它开通一个新环境；停用一个仓库，会回收它的环境。
