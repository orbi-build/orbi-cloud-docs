状态页在 **[orbi.build/api/](https://orbi.build/api/)**，你在这里看 Orbi 正在做什么、什么需要你、以及你用了多少。

页面按你要做的事排序，不按功能排。从上到下依次是：

1. **顶栏**：左边是 **Orbi**（点它总能回到这里），右边是你的头像和账户菜单。
2. **下一步**：现在在发生什么，以及你此刻该做的那一件事。
3. **仓库概览**：每个绑定的仓库一行。
4. **交付记录**：所有工作，分在三个标签页里。
5. **设置与参考**：用量、仓库和版本，默认折叠，点开才显示。
6. **页脚**：技术支持、服务状态、隐私政策、服务条款和 GitHub。

## 下一步

**下一步** 卡片是页面上最先要看的部分。它依次包含：

- **开通进度**：七个开通步骤（见下文）。七步全部完成后，它会折叠成 **开通完成 · 7/7**。
- 一句**标题**：用一句话概括你账户当前的状态。
- **① 需要你处理** 或 **① 操作提醒**：等你处理的事项，每一项都带着处理它的按钮。没有东西需要你时这部分不出现，这是好消息。
- **挑一张让 Orbi 试试**：Orbi 空闲时出现，列出一张新手演示票和你还没打标签的 Issue，每张都带 **试试 →**。见[第一个 Issue](/zh/first-issue)。
- 有明确下一步时，页面上唯一的实心按钮。比如 Orbi 做完了、在等更多工作时，这个按钮是 **创建 Issue**。

### 标题

| 标题 | 含义 |
|---|---|
| **先连接一个仓库** | 还没有绑定任何仓库 |
| **Orbi 正在准备运行环境** | [开通](/zh/provisioning)正在进行，通常要一到两分钟 |
| **开通失败，平台会自动重试** | 开通因临时原因失败，Orbi 会自己重试 |
| **开通失败，平台正在自动恢复** | 平台侧故障，不需要你操作，见[开通](/zh/provisioning) |
| **Orbi 在等你的第一个 Issue** | 已就绪。给一张 Issue 打上 `ai-ready`，或者用 **试试 →** |
| **Orbi 正在写代码** | 有一次交付正在进行 |
| **Orbi 正在评审 PR #N，通过后自动合并** | 独立评审正在进行 |
| **PR #N 需要你 approve** | 分支保护要求合并前有人批准，见[分支保护](/zh/connect-repository) |
| **Orbi 需要你确认一下** | 有一个结果在等人确认 |
| **Orbi 卡住了，需要你看一下** | 有 Issue 受阻，或者你那边有东西要修；**① 需要你处理** 下面的那一项会说清是哪个 |
| **Orbi 待命中** | 没有在跑的工作；可能有 Issue 在当前交付范围之外等着，或者需要你看一下 |
| **Orbi 已完成，等你的下一个 Issue** | 所有工作都做完了，Orbi 在等下一张 Issue |
| **暂时读不到 Orbi 的状态** | Orbi 此刻读不到你的交付状态；卡片上会给出刷新或重新连接的入口 |

有两种情况会用自己的出路替换掉标题下常规的按钮：

- **免费的 3 次交付已用完**：带一个 **订阅** 按钮。见[付费](/zh/billing)。
- **本月额度已用完**：Orbi 暂停认领新的 Issue，已经在跑的交付照常完成。卡片提供 **绑定自己的模型 key**，Solo 套餐还会提供升级到 Pro。见[额度与限制](/zh/limits-and-quotas)。

### 开通进度

七个步骤跟踪开通过程：**登录 → 安装 App → 连接仓库 → 开通环境 → 首个 Issue → 发一个版本 → 订阅**。每一步标记为 **✓ 已完成**、**等你**、**等系统** 或 **失败**；当前步骤会高亮，并带一个 **看这一步怎么做 ▶** 链接，点开播放这一步的短视频。还在用免费交付的账户，最后一步显示为 **前 3 次交付免费，之后订阅**，旁边有一段折叠的 **价格说明与账户**。

## 仓库概览

一张表，表头是 **仓库 N / 上限 M**，旁边有 **添加仓库** 按钮。每个绑定的仓库一行，显示它有多少 Issue 处于 **进行中**、**评审中** 和 **已完成**。需要注意的行会带一个标签：**需要你**、**自动重试中** 或 **平台恢复中**。

有多个仓库时，点某一行会打开这个仓库自己的视图：它的基础分支和当前交付范围、**在 GitHub 查看** 和 **创建 Issue**、它现在在发生什么、它的交付记录、它的版本，以及 **停用此仓库**。见[多个仓库](/zh/connect-repository)。

## 交付记录

你的工作分在三个标签页里，每张 Issue 只出现在其中一个：

| 标签页 | 里面是什么 |
|---|---|
| **进行中** | 还没有 pull request 的未结束工作：排队中、正在写代码、在等补充信息，或在开 pull request 之前受阻 |
| **评审中** | 已经有 pull request 的未结束工作：正在过独立评审、正在修复、在等你批准，或在评审之后受阻 |
| **已完成** | 结束了的工作：已合并，或已关闭 |

每一行显示 Issue（链到 GitHub）、状态标签、它的 pull request 和最后更新时间。交付上报用量之后，标题下方会显示用量：运行时长、模型请求、输入和输出 tokens、缓存使用。排队中的工作则显示 **已排队** 或 **在等前置 Issue 完成**。

状态标签对应[交付生命周期](/zh/delivery-lifecycle)里描述的那些标签：**已排队**、**进行中**、**PR 评审中**、**修复中**、**等待审批**、**待补充**、**等你确认**、**受阻**、**已合并**、**已关闭**。打开 Issue，就能在 Orbi 的评论里看到原因和下一步。

## 设置与参考

默认折叠，点 **设置与参考** 展开。

<Frame caption="展开后的设置与参考：本月用量、绑定的仓库和版本">
  <img src="/images/zh/status-settings.png" alt="展开后的设置与参考：本月用量、绑定的仓库和版本" />
</Frame>

**本月用量**。一行显示本自然月已用的 tokens 与你套餐额度的对比、已用的百分比，以及 **缓存命中率**，下面一根进度条，到 80% 变琥珀色，到 100% 变红色。用自己的模型 key 时，这一行显示为 **本月用量（你的 key）**，没有上限。缓存命中率低值得留意：缓存未命中的 tokens 成本大约是命中的 50 倍，额度会消耗得快得多。见[额度与限制](/zh/limits-and-quotas)。

**绑定的仓库**。每个仓库和它的 **基础分支**、**开通状态**；开通失败时还会显示原因、发生时间、**request id** 和下一步。你断开过的仓库列在 **历史仓库** 下面，历史记录都还在。

**版本**。当前交付范围、你未发布的版本（带 **开始交付** 和 **发版** 两个操作），以及一个 **新建版本** 输入框。见[发版](/zh/releases)。

还在用免费交付的账户，第一次交付合并之后，这里还可能出现一段 **创始会员优惠** 说明。

## 账户菜单和页脚

订阅、**模型配置**、语言、技术支持、这份文档和 **退出登录** 都在头像下的账户菜单里，见[账户菜单](/zh/sign-in)。

每个页面的页脚都链到 **技术支持（Telegram）**、**服务状态**（服务状态页）、**隐私政策**、**服务条款** 和 **GitHub**。

## 刷新

开通正在跑的时候页面会自己刷新，那一两分钟你可以把它开着不管。其他时候重新加载就能拿到当前状态。它实时读 GitHub，显示的是你 Issue 的真实状态，不是缓存副本。

如果 Orbi 此刻连不上 GitHub，页面会说 **暂时读不到 Orbi 的状态**，或者说交付数据暂时不可用，不会给你一个误导人的空列表。
