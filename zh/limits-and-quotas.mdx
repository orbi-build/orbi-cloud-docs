有三个限制：订阅前的 3 次合并交付免费额度，按套餐不同的每月 token 额度，以及同时能连接几个仓库的上限。

哪一个都不会打断已经在跑的交付。

## 一览

| | 免费 | Solo | Pro |
|---|---|---|---|
| 交付次数 | 前 3 次合并的交付 | token 额度内不限 | token 额度内不限 |
| 每月模型 tokens | 3 次交付用不到上限 | 1 亿（100,000,000） | 3 亿（300,000,000） |
| 同时连接的仓库 | 1 | 1 | 5 |

价格和按年付费的选项见[价格页](https://orbi.build/cloud/?ref=cloud-docs-limits)，订阅怎么操作见[计费](/zh/billing)。

## 免费额度

前 **3 次合并的交付免费**，不用绑卡，不用订阅。

名额在你给 Issue 打上 `ai-ready` 时占用，如果那次交付最终没有合并，名额会**退回** —— 落到 `ai-blocked` 的 Issue，或者你自己关掉而没有合并的 Issue，都会把名额还回来。所以这个额度的口径是「3 次**合并**的交付」，而不是「3 次尝试」。

计数按 Issue 且幂等：给同一张 Issue 重新打标签不会再消耗一个名额。退回之后重新交付同一张 Issue，用的是它自己还回来的那个名额。

用的过程中 Orbi 会随时告诉你还剩多少：免费交付合并时的评论会写明还剩几次免费交付，状态页的**下一步**卡片里也会显示**前 3 次交付免费，还剩 N 次**。

### 额度用完时

你下一次打上 `ai-ready` 的 Issue，标签会被摘掉，并收到一条评论说明免费交付已用完，附订阅链接。状态页会显示**免费的 3 次交付已用完**和**订阅**按钮，开通进度的最后一步显示为**前 3 次交付免费，之后订阅**。

**怎么恢复**：订阅，然后**重新给这张 Issue 打上 `ai-ready` 标签**。标签不会自动恢复。额度用完那一刻已经在途的交付会正常跑完。

## 每月 token 额度

订阅包含模型用量：**Solo 每月 1 亿 tokens，Pro 每月 3 亿 tokens**，按自然月（UTC）计算。没有按 token 的超额计费。

用量统计包括输入 tokens、输出 tokens 和缓存读取 tokens。重新交付同一张 Issue 会累加：每次交付都是一次独立的运行。

这些额度够跑多少次交付，取决于任务大小、代码库大小和 prompt caching。[价格页](https://orbi.build/cloud/?ref=cloud-docs-limits)上有当前的实测区间。

### 看你的用量

在状态页打开**设置与参考**。**本月用量**这一行显示已用 tokens 和额度上限、已用百分比以及**缓存命中率**，下面的进度条到 80% 变成琥珀色，到 100% 变成红色。

缓存命中率比看上去重要。缓存未命中的 token 单价大约是命中的 **50 倍**，命中率低会明显更快烧掉额度。如果你的命中率偏低，先搞清楚原因，再下「额度不够用」的结论。

**交付记录**里的每条工作也会显示自己的用量：运行时长、模型请求数、输入和输出 tokens、缓存使用情况。没有上报用量的工作显示 `—`。

### 月额度用完时

Orbi 会**暂停认领新的 Issue**。你打的 `ai-ready` 标签原样保留，已经在跑的交付正常跑完。

**下一步**卡片会显示**本月额度已用完：Orbi 暂停认领新的 Issue，进行中的交付会照常完成。**，并给出几条出路：

- **绑定自己的模型 key**。在**模型配置**里保存 key 后立即恢复交付，不受额度限制，见[模型配置](/zh/model-configuration)。
- **升级到 Pro**（Solo 套餐才有这一项），每月 3 亿 tokens。
- **或者等**。下个月 1 日（UTC）额度重置，排队的 Issue 会自动开始，不需要重新打任何标签。

## 仓库数量上限

免费和 Solo 同一时间只能连接**一个仓库**，Pro **最多五个**。免费套餐上，连接另一个仓库会替换当前的仓库。Solo 和 Pro 到达上限后再连接仓库会被拒绝，并显示**已达到仓库数量上限**：先停用一个，Solo 也可以升级到 Pro。见[连接仓库](/zh/connect-repository)。另外，免费套餐有交付在途时不能更换仓库。

## 永远不会被打断的东西

任何限制都不会停掉正在进行的工作。处在 `ai-in-progress`、`ai-pr-opened` 或 `ai-fix-needed` 的交付，无论如何都会跑完。

平台升级和部署也有同样的性质：它们不会重启一个已经在执行的交付。

## 小结

| 限制 | 数值 | 到顶时 | 怎么恢复 |
|---|---|---|---|
| 免费额度 | 3 次合并的交付 | 摘掉 `ai-ready`，评论附订阅链接 | 订阅，重新打 `ai-ready` |
| 每月 tokens | Solo 1 亿 · Pro 3 亿，按自然月（UTC） | 新 Issue 排队等待，标签保留 | 每月 1 日（UTC）自动恢复；绑定自己的 key 或升级则立即恢复 |
| 仓库数 | 免费和 Solo 1 个 · Pro 5 个 | 免费：连接新仓库会替换旧的。Solo 和 Pro：到上限后被拒绝 | 先停用一个仓库，或升级 |
| 认领间隔 | 最长 5 分钟 | — | — |
