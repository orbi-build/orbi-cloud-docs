有三个限制：订阅前的 3 次合并交付免费额度，按付费套餐不同的每月 token 额度，以及同时能连接几个仓库的上限。

哪一个都不会打断已经在跑的交付。

## 一览

| | 免费 | Solo | Pro |
|---|---|---|---|
| 交付次数 | 前 3 次合并的交付 | token 额度内不限 | token 额度内不限 |
| 每月模型 tokens | 页面不显示月度额度，以免费次数为限 | 4 亿（400,000,000） | 12 亿（1,200,000,000） |
| 同时连接的仓库 | 1 | 1 | 5 |

价格和按年付费的选项见[价格页](https://orbi.build/cloud/?ref=cloud-docs-limits)，订阅怎么操作见[付费](/zh/billing)。

## 免费额度

前 3 次合并的交付免费，不用绑卡，不用订阅。

名额在你给 Issue 打上 `ai-ready` 时占用，如果那次交付最终没有合并，名额会退回：落到 `ai-blocked` 的 Issue，或者你自己关掉而没有合并的 Issue，都会把名额还回来。所以这个额度的口径是 3 次*合并*的交付，而不是 3 次尝试。次数不按月重置。

计数按 Issue 且幂等：给同一张 Issue 重新打标签不会再消耗一个名额。退回之后重新交付同一张 Issue，会重新占一个名额。

用的过程中 Orbi 会随时告诉你还剩多少：免费交付合并时的评论会写明还剩几次免费交付。状态页的「下一步」卡片里会显示「免费还剩 N 次（共 3 次）。」，「开通进度」的最后一步显示为「前 3 次免费」，鼠标悬停在上面会说明怎么算一次。

### 额度用完时

你下一次打上 `ai-ready` 的 Issue，标签会被摘掉，并收到一条评论说明免费交付已用完，附订阅链接。状态页会显示「免费的 3 次已用完：」「订阅后继续 →」和「订阅」按钮。

怎么恢复：订阅，然后重新给这张 Issue 打上 `ai-ready` 标签。标签不会自动恢复。额度用完那一刻已经在途的交付会正常跑完。

## 每月 token 额度

付费订阅包含模型用量：Solo 每月 4 亿 tokens，Pro 每月 12 亿 tokens，按自然月（UTC）计算。状态页把重置时间写成每月 1 日北京时间 8:00，和 UTC 0 点是同一个时刻。没有按 token 的超额计费。免费账户的页面不显示月度额度，用量以免费次数为限。

用量统计包括输入 tokens、输出 tokens 和缓存读取 tokens，三者按同样的分量计入。重新交付同一张 Issue 会累加：每次交付都是一次独立的运行。

这些额度够跑多少次交付，取决于任务大小、代码库大小和 prompt caching。[价格页](https://orbi.build/cloud/?ref=cloud-docs-limits)上有当前的实测区间。

### 看你的用量

在状态页打开「用量与设置」。付费账户的「本月 AI 用量」这一行显示已用 tokens 和额度上限、「已用」百分比、「其中缓存」占比和重置时间，下面的进度条到 80% 变成琥珀色，到 100% 变成红色。免费账户这一行只显示已用 tokens，没有上限、百分比和进度条。

「其中缓存」是本月用量里缓存读取所占的比例。缓存读取的 tokens 和输入、输出一样计入额度，不会更省。如果有任务的用量没有上报，这一行会写明有几个任务没有计入。

### 月额度用完时

Orbi 会暂停认领新的 Issue。你打的 `ai-ready` 标签原样保留，已经在跑的交付正常跑完。

「下一步」卡片会显示「本月 AI 用量已用完：Orbi 暂停接新任务，进行中的会照常做完。」，并给出几条出路：

- 「改用自己的 API key」：保存 API key 后立即恢复，不占本月用量，由你的 AI 模型服务商计费，见[模型配置](/zh/model-configuration)。
- 「升级到 Pro」（Solo 套餐才有这一项），每月 12 亿 tokens。
- 或者等：下个月 1 日北京时间 8:00（UTC 0 点）额度重置，排队的 Issue 会自动开始，不需要重新打任何标签。

## 仓库数量上限

免费和 Solo 同一时间只能连接一个仓库，Pro 最多五个。所有套餐规则一样：到了上限再连接新仓库会被拒绝，并显示「已达到仓库数量上限」，点「去断开仓库」先断开一个，再连新的。断开不会改动 GitHub 上的仓库。免费和 Solo 也可以升级到 Pro。见[连接仓库](/zh/connect-repository)。

## 永远不会被打断的东西

任何限制都不会停掉正在进行的工作。处在 `ai-in-progress`、`ai-pr-opened` 或 `ai-fix-needed` 的交付，无论如何都会跑完。

平台升级和部署也有同样的性质：它们不会重启一个已经在执行的交付。

## 小结

| 限制 | 数值 | 到顶时 | 怎么恢复 |
|---|---|---|---|
| 免费额度 | 3 次合并的交付 | 摘掉 `ai-ready`，评论附订阅链接 | 订阅，重新打 `ai-ready` |
| 每月 tokens | Solo 4 亿 · Pro 12 亿，按自然月（UTC） | 新 Issue 排队等待，标签保留 | 每月 1 日北京时间 8:00（UTC 0 点）自动恢复；改用自己的 API key 或升级则立即恢复 |
| 仓库数 | 免费和 Solo 1 个 · Pro 5 个 | 再连新仓库会被拒绝 | 先断开一个仓库，或升级 |
| 认领等待 | 一般 1 分钟内，最长约 5 分钟 | 无 | 无 |
