有三个限制：免费试用的有效期、平台模型的每月 token 额度，以及同时能连接几个仓库的上限。

哪一个都不会打断已经在跑的交付。

## 一览

| | 免费试用 | Solo | Pro |
|---|---|---|---|
| 交付 | 试用期内不限次数，受 token 额度限制 | token 额度内不限 | token 额度内不限 |
| 每月平台模型 tokens | 6000 万（60,000,000） | 4 亿（400,000,000） | 12 亿（1,200,000,000） |
| 同时连接的真实项目 | 1 | 1 | 5 |

价格和按年付费的选项见[价格页](https://orbi.build/cloud/?ref=cloud-docs-limits)，订阅怎么操作见[付费](/zh/billing)。

## 免费试用

完成 GitHub App 安装并建立 Orbi 账号时，即完成注册，开始 14 天免费试用，不用绑卡。

示例仓库另有一次 14 天试用，从你第一次开始示例任务时起算，只给一次。即使注册试用已经到期，还没用过这次额外试用，也可以开始示例任务。试用到期时间取「注册时间 + 14 天」和「首次开始示例任务的时间 + 14 天」中更晚的一个；同一个到期时间适用于示例仓库和普通仓库。

试用期内交付不限次数。平台模型用量上限为每自然月（UTC）6000 万 tokens，先用平台额度；平台用量和自带 key 的用量分开统计。

### 试用用量到上限时

已经配置自己 API key 的，改用自己的 key 继续交付。没有配置的，Orbi 暂停认领新任务，状态页显示「试用用量已用完，暂停接新任务」并提供订阅入口。保存自己的 API key 或订阅后可恢复；正在进行的交付正常完成。

用量按自然月统计。跨月时额度会重置，但试用到期时间不变。

### 试用到期时

除上面所述的首次示例任务外，试用到期后新打上 `ai-ready` 的 Issue 会被摘掉标签，评论说明「免费试用已结束」并附订阅入口。订阅后，被拦下且仍开着的 Issue 会自动重新开始，不用再打标签。正在进行的交付不会被打断。

已订阅用户不显示试用信息。

## 每月 token 额度

付费订阅包含模型用量：Solo 每月 4 亿 tokens，Pro 每月 12 亿 tokens，按自然月（UTC）计算。状态页把重置时间写成每月 1 日北京时间 8:00，和 UTC 0 点是同一个时刻。没有按 token 的超额计费。

用量统计包括输入 tokens、输出 tokens 和缓存读取 tokens，三者按同样的分量计入。重新交付同一张 Issue 会累加：每次交付都是一次独立的运行。

这些额度够跑多少次交付，取决于任务大小、代码库大小和 prompt caching。[价格页](https://orbi.build/cloud/?ref=cloud-docs-limits)上有当前的实测区间。

模型用量包含交付、写需求草稿和获取建议；各自的输入、输出、缓存读取 token 都计入。平台用量和自带 key 的用量分开记录。

### 看你的用量

在状态页打开「用量与设置」。「本月 AI 用量」显示平台已用 tokens 和缓存占比。试用中或已订阅的账户还显示当前额度上限、「已用」百分比和重置时间，进度条到 80% 变成琥珀色，到 100% 变成红色。

「其中缓存」是本月用量里缓存读取所占的比例。缓存读取的 tokens 和输入、输出一样计入额度，不会更省。如果有任务的用量没有上报，这一行会写明有几个任务没有计入。

### 月额度用完时

付费套餐的月度额度用完且没有配置自己的 API key 时，Orbi 会暂停认领新的 Issue。你打的 `ai-ready` 标签原样保留，已经在跑的交付正常跑完。

状态主卡会显示「本月 AI 用量已用完：Orbi 暂停接新任务，进行中的会照常做完。」，并给出几条出路：

- 「改用自己的 API key」：保存 API key 后立即恢复，不占本月用量，由你的 AI 模型服务商计费，见[模型配置](/zh/model-configuration)。
- 「升级到 Pro」（Solo 套餐才有这一项），每月 12 亿 tokens。已经按期订阅 Solo 的，卡上显示的是「要升级到 Pro，直接联系我们：」和邮箱、Telegram 群链接。
- 或者等：下个月 1 日北京时间 8:00（UTC 0 点）额度重置，排队的 Issue 会自动开始，不需要重新打任何标签。

## 仓库数量上限

所有套餐都可额外连接一个经核实的官方示例副本，不占真实项目名额。

免费和 Solo 同一时间只能连接一个真实项目，Pro 最多五个。所有套餐规则一样：到了上限再连接新仓库会被拒绝，并显示「已达到仓库数量上限」，点「去断开仓库」先断开一个，再连新的。断开不会改动 GitHub 上的仓库。免费账户也可以直接订阅 Pro；已订阅 Solo 的，联系我们升级。见[连接仓库](/zh/connect-repository)。

## 永远不会被打断的东西

任何限制都不会停掉正在进行的工作。处在 `ai-in-progress`、`ai-pr-opened` 或 `ai-fix-needed` 的交付，无论如何都会跑完。

平台升级和部署也有同样的性质：它们不会重启一个已经在执行的交付。

## 小结

| 限制 | 数值 | 到顶时 | 怎么恢复 |
|---|---|---|---|
| 免费试用有效期 | 注册起 14 天；示例另有一次 14 天，取更晚的到期时间 | 摘掉新票的 `ai-ready`，评论附订阅链接 | 订阅后被拦的 Issue 自动开始；尚未用过的示例试用也可按上文开始 |
| 试用平台用量 | 每自然月（UTC）6000 万 tokens | 有自己的 key 则改用自己的；否则暂停认领新任务 | 保存自己的 API key 或订阅；跨月重置后仍须在试用期内 |
| 付费套餐每月 tokens | Solo 4 亿 · Pro 12 亿，按自然月（UTC） | 没有自己的 key 时，新 Issue 排队等待，标签保留 | 每月 1 日北京时间 8:00（UTC 0 点）自动恢复；改用自己的 API key 或升级则立即恢复（已订阅 Solo 的联系我们升级） |
| 真实项目名额 | 免费和 Solo 1 个 · Pro 5 个 | 再连新仓库会被拒绝 | 先断开一个仓库，或换 Pro（已订阅 Solo 的联系我们） |
| 认领等待 | 一般 1 分钟内，最长约 5 分钟 | 无 | 无 |
