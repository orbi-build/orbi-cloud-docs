从状态页开始：「下一步」卡片的标题说明你当前处在什么状态，等你处理的事项都列在「需要你处理」下面，旁边就是修它的按钮。

Orbi Cloud 里几乎每个失败状态都会自己说明自己。这一页按用户实际碰到的顺序，讲每个状态的含义和处置。

## 不知道下一步该做什么

看状态页顶部的「开通进度」。高亮的那一步就是在等你的那一步，点它的「看这一步怎么做 ▶」链接会播放一段短视频，演示的正是这一步。[快速开始](/zh/quickstart)用文字走了同样的七步。

如果仓库已经连上、工作环境也准备好了，但还没开始任何工作，「下一步」卡片里会列出你仓库里已有的 Issue。点其中一张旁边的「让 Orbi 做这个」，或者点「写需求」用一句话说要改什么。见[第一张 Issue](/zh/first-issue)和[写需求](/zh/write-a-requirement)。

## 打了标签但什么都没发生

按顺序查：

1. **这张 Issue 真的带了 `ai-ready` 吗？** 这是最常见的原因。光写 Issue 不够，开始干活的信号是这个标签。去 GitHub 上看一下 Issue 的标签。状态页的「让 Orbi 做这个」和写需求页的「交给 Orbi 开始做」会替你打上这个标签。
2. **它在已连接的仓库里吗？** Orbi 只读你连接的仓库里的 Issue。看状态页上的项目概览。
3. **工作环境准备好了吗？** 「开通进度」里的「准备工作环境」必须显示「已完成」。在那之前没有环境可以跑交付。
4. **过了 5 分钟吗？** 打上标签后一般 1 分钟内就会唤醒 Orbi，每 5 分钟一次的定时器是兜底。
5. **标签是不是被摘掉了，还多了一条评论？** 你的免费交付用完了，见[额度与限制](/zh/limits-and-quotas)。订阅，然后重新打标签。
6. **页面上写着「本月 AI 用量已用完，暂停接新任务」吗？** 新 Issue 会一直等到额度重置，或者等你绑定自己的模型 key，标签不会被摘。见[额度与限制](/zh/limits-and-quotas)。
7. **页面上写着「有任务不在当前版本里，暂时不会做」吗？** 你设了当前版本（交付范围），而这张 Issue 不在那个版本的里程碑里。把它挪进这个版本，或者切换当前版本，见[发版](/zh/releases)。
8. **这张 Issue 是不是已经带了别的 `ai-*` 标签？** 已经是 `ai-in-progress` 或 `ai-merged` 的 Issue，再打一次 `ai-ready` 不会重新派发。

如果「进行中」标签页写着工作环境准备失败，原因在「用量与设置」→「已连接的项目」里。

## `ai-blocked`

`ai-blocked` 是**有意的停止**，不是崩溃。它的含义是：自动恢复不安全，需要一个人来决定下一步。状态页会显示「Orbi 卡住了，需要你看一下」，并写明是哪张 Issue。

**先读 Orbi 留在 Issue 上的那条评论**，它写了为什么进行不下去。Orbi 记下了原因时，状态页上的卡片会用一句话概括，卡片上的「查看 Orbi 的说明」按钮直接打开那条评论；没有记下原因时，按钮是「在 GitHub 查看（Issue #N）」。常见原因：

- 修复循环跑完了允许的轮次，仍然没拿到干净的评审结论。
- 缺少一个外部前置条件，也就是交付自己无法安全判断或修复的东西。
- 发版用的里程碑不存在。遇到这种情况，状态页会提供「创建版本并继续」。
- Issue 要求的事情，交付环境做不到（见下）。

**怎么恢复**：先修掉根因，然后重新打上 `ai-ready`。修根因经常意味着改 Issue 本身：把验收标准写清楚、删掉做不到的要求，或者拆成更小的 Issue。

<Note>
只摘掉 `ai-blocked` 标签不会重启任何东西，只留一条评论也不会。修掉原因，然后重新打 `ai-ready`，这才是把 Issue 放回队列的动作。
</Note>

Issue 被 block 时，PR、分支和工作区都会完整保留，你的东西不会丢。

### 环境满足不了的验收标准

Issue 被 block 的一个高频原因，是要求了交付环境里不可能存在的证据。那个环境有你的仓库和你的测试，**没有**你的生产凭据、第三方账号、对着线上站点的真实浏览器，也没有你的部署流水线。

写着「部署到生产并确认」「登录线上后台截图」「用真实失效的 token 复现」这类验收标准的 Issue，会空转然后 block。把它改写成仓库内可验证的东西，比如断言渲染出的文案、断言错误分类、断言不该出现的内容；生产侧的证据由你自己去取。

## Orbi 需要更多信息

任务状态显示「待补充」（`ai-needs-detail`），状态页上会出现一张说这张 Issue「需要你补充信息」的卡片。先点「查看 Orbi 的提问」看缺什么，再点「补充需求」。这会打开写需求页，你在那里补充好的内容会追加到 Issue 正文，Issue 也会自动回到 `ai-ready`。

也可以在 GitHub 上处理：按 Orbi 的提问改 Issue 正文，然后重新打上 `ai-ready`。Orbi 再次认领时读的是 Issue 正文，只在评论里回答是不够的。

## PR 在等我批准

标题显示「需要你在 GitHub 上批准这次改动」，任务状态显示「等你批准」。你的分支保护要求一个 approving review，而 Orbi 不能自己批准自己。批准这个 PR，或者改掉这条规则，见[分支保护](/zh/connect-repository)。

## PR 写得不对

在 Issue 上评论说明要改什么，或者直接编辑 Issue 正文。正在跑的交付会带着你的修正重启，不需要关掉什么，也不需要取消。见[中途调整交付](/zh/delivery-lifecycle)。

如果这个工作干脆不要了，关掉 Issue。如果那是一次免费交付，关闭且未合并会把名额退回来。

## 工作环境准备失败

「下一步」卡片会说明这件事是需要你处理、正在重试，还是平台正在恢复；点「查看原因与处理方法」会跳到「用量与设置」→「已连接的项目」，那里有原因、发生时间、「出错编号」和下一步。一共四类，完整说明在[准备工作环境](/zh/provisioning)：

| 原因 | 怎么办 |
|---|---|
| Orbi 的 GitHub App 安装或授权已失效 | 点「重新授权 GitHub App」，再回到状态页查看 |
| API key 未被接受 | 点「设置 AI 模型」改正 key；保存后自动重试 |
| 无法连接 AI 模型服务（API key 或 baseUrl 可能有误） | 检查 baseUrl 和 key，用「测试连接」试一下；保存后自动重试 |
| 工作环境准备失败（Orbi 这边的问题） | 什么都不用做，平台会自动恢复。晚点回来看 |

联系支持时把出错编号一起发过去。旁边的邮件联系链接会自动把出错编号写进邮件标题。

## 连不上仓库

| 你看到的 | 怎么修 |
|---|---|
| 仓库不在列表里 | 展开「没找到你的仓库？」，按说明到「GitHub App 设置」的 Repository access 里把仓库加进去，点 Save，再回来刷新 |
| 仓库名后面标着「（Issues 已关闭，需先开启）」，或者因为 Issues 被关闭而显示「无法连接仓库」 | 在仓库 **Settings → Features → Issues** 里打开 Issues，然后点「返回重试」 |
| 「已达到仓库数量上限」 | 先断开一个不再需要的仓库（「去断开仓库」）；Free 和 Solo 也可以升级到 Pro |
| 无法从 GitHub 获取仓库列表 | 稍后刷新；一直失败的话，在下面的输入框里按 `所有者/仓库名` 直接填写 |
| 仓库名格式不对 | 按 `所有者/仓库名` 填写 |

完整说明见[连接仓库](/zh/connect-repository)。

## GitHub App 被卸载了

状态页会检测到并提示「Orbi 的 GitHub App 已被卸载，重新安装后才能继续。」，给出「重新安装 GitHub App」。在同一个账号下重新安装会接回你原来的租户，历史和配置都还在。之后可能需要重新连接一次仓库。

## 仓库的 Issues 被关掉了

如果连接之后 Issues 功能被关了，状态页会说明。重新打开 **Settings → Features → Issues**。Orbi 的整个输入通道就是 Issues，关掉之后什么都跑不了。

## 额度掉得比预期快

打开「用量与设置」，看「本月 AI 用量」那一行的「其中缓存」百分比。缓存读取的 tokens 和输入、输出一样计入额度，所以缓存占比高低不会改变额度消耗的速度；额度用得快，是因为任务本身用的 tokens 多。「任务记录」里每个任务下面的用量那一行，能让你看出哪次交付特别贵。

大而模糊的 Issue 比小而具体的 Issue 贵得多，tokens 和修复轮次都是。

## 任务没有显示用量

「任务记录」里某个任务下面没有用量那一行，说明那条工作没有上报用量统计。这是采集上的缺口，不代表交付失败。「本月 AI 用量」那一行会注明有几个这样的任务没有计入。

## 登录过期了

重新登录。什么都不会丢：仓库连接、模型配置和任务记录属于你的租户，不属于浏览器会话。

## 页面语言不对

打开账户菜单（右上角的头像），选「🇨🇳 ZH」或「🇺🇸 EN」。在登录页，右上角有同样的切换。选择会在这个浏览器上保存一年。

## 怎么找人

| 什么事 | 找哪里 |
|---|---|
| 提问、有东西不工作、怎么操作 | Telegram 群：账户菜单里的「加入 Telegram 群获取技术支持」，或者每个 Orbi Cloud 页面页脚的「Telegram 群」。公开频道是 [t.me/orbi_build](https://t.me/orbi_build) |
| 账单、退款、账户和隐私 | 发邮件到 **support@orbi.build**，或用账户菜单里的「发邮件给我们」 |
| 愿意公开报告的 bug：账户菜单或页脚里的「报告 bug（GitHub，公开）」；开源引擎里能复现的 bug 也在这里 | [orbi-build/orbi 的 GitHub Issues](https://github.com/orbi-build/orbi/issues) |

回复时间没有保证，但信息给得全的报告会快得多。请带上：

- 你做了什么、预期是什么。
- Issue 或 PR 的链接。
- 如果涉及工作环境准备失败，带上出错编号。
- 状态页的原话：标题的准确措辞，以及「需要你处理」下面那一项的准确措辞。

**永远不要**把 API key、token 或任何凭据贴进支持消息、Issue 或 PR。

如果这里某一页和产品实际显示的不一致，也值得报告：在 [orbi-build/orbi-cloud-docs](https://github.com/orbi-build/orbi-cloud-docs/issues) 开一个 issue。
