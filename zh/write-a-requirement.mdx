Issue 不一定要自己写。在状态页（登录后的首页）点「写需求」，用一两句话说要改什么，Orbi 会读你仓库里的代码，通常一两分钟就起草好一张 GitHub Issue。你看过草稿、点了提交，才会真的在仓库里建 Issue。

## 写好并提交

1. 在状态页点「写需求」。[连接了仓库](/zh/connect-repository)之后才有这个按钮；连了好几个仓库的话，在页面上的下拉框里选要改的那个。
2. 用大白话说要改什么，比如「首页太慢了，看看能不能快一点」。一句话就够，写长一点也没关系。然后点「让 Orbi 帮我写清楚」。
3. Orbi 读代码、写草稿，通常要一两分钟。刚连接的仓库要先等运行环境[开通](/zh/provisioning)，再多一两分钟，这期间页面同样显示「Orbi 正在写」，所以第一份草稿可能要三四分钟。这期间可以关掉页面，回头点「写需求」，再点「接着改上次那份」就能接着看。有时 Orbi 还会附带几个问题让你确认，见下面的「Orbi 拿不准的时候」。
4. 读一遍草稿。里面写着要做什么、做完以后你的用户能看到什么、哪些不在这次范围里，以及你的话没说清的地方 Orbi 是按什么理解的。
5. 点「就这样，开始做」。Orbi 在你的仓库里建好 Issue，自带派发标签（默认是 `ai-ready`），交付通常一分钟内开始。有两种情况不会开始：免费次数已经用完（见下面的「用量」），或者你的项目有一项里程碑设置要先改好。第二种情况下，页面会告诉你需求已经交上了，交付开始之前不占用次数和额度。这不是你配置错了，你也不用改仓库里的任何东西：[联系我们](/zh/troubleshooting#怎么找人)，我们改好设置后这张 Issue 就会被认领，不用你重新提交。

## Orbi 拿不准的时候

你的需求有不止一种理解时，Orbi 会先问你，不会自己瞎猜。每个问题有几个选项，Orbi 已经先选了它推荐的那项。你会看到下面两种情况之一：

- **草稿下面列着问题。** 草稿已经按推荐项写好，你同意的话什么都不用改，直接开始做。不是你的意思就点别的选项，或者选「都不是，我自己说」，写下你的回答；然后点「按我选的重新写」，大约一分钟草稿就会更新，更新完才能开始做。
- **只有问题，还没有草稿。** 同样选好答案，再点「按我选的写」就会生成草稿。

想改别的地方，在草稿下面的回复框里写清楚发出去。Orbi 会改写草稿，同样大约一分钟，你前面说过的它都记得，不用再说一遍。

## 建出来的 Issue 长什么样

就是你连接的仓库里一张普通的 GitHub Issue。第一行写明「由 @你的账号 通过 Orbi 提交」，下面是你确认过的草稿原文，一字不改。它会带上仓库设置的派发标签（仓库的 `.github/orbi.toml` 没另设标签的话就是 `ai-ready`），并挂上仓库「当前交付范围」对应的里程碑（设了的话，见[发版](/zh/releases)）。

每个仓库同一时间只有一份草稿。没提交的草稿在最后一次修改后保留 7 天。在同一个仓库开始写新的需求会替换掉它，替换之前页面会提醒你。已经提交的 Issue 留在你的仓库里，不受影响。

## 用量

- 写草稿不计用量，草稿的数量也没有单独的上限。
- 提交的 Issue，计次规则和你手动打 `ai-ready` 的 Issue 相同。
- **免费档**：免费交付次数在账号开通时一次发放，不按月重置。提交一张 Issue 占用一次；交付失败或最终没有合并的，这一次会退还。次数用完后仍然可以写草稿，但提交的 Issue 会被摘掉派发标签（默认是 `ai-ready`）；订阅之后，你自己给它重新打上这个标签，交付才会开始。
- **付费档**：当月额度用完、交付暂停时，写草稿也会暂停，额度重置后一起恢复。这一条只对付费档；免费档次数用完后照样可以写草稿。详见[额度与限制](/zh/limits-and-quotas)。

## 什么时候自己写 Issue 更好

如果你已经清楚要什么，也能列出怎么验收，[直接在 GitHub 上开 Issue](/zh/first-issue) 更快。写需求最有用的时候，是你知道要解决什么问题，却不知道该改代码的哪里。
