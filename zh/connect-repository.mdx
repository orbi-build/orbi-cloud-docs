连接仓库是告诉 Orbi 它可以处理哪个仓库的 Issue，以及往哪个分支提交拉取请求。

连接是自助的：你在连接页上挑好仓库和基础分支，Orbi 随即开始准备工作环境。连接时 Orbi 不会在你的仓库里新建 Issue。同一时间能连几个仓库取决于你的套餐：Free 和 Solo 是一个，Pro 最多五个。换仓库一律要先断开旧的。详见[额度与限制](/zh/limits-and-quotas)。

## 连接

还没连过仓库时，状态页的「下一步」卡片写着「先连接一个 GitHub 仓库」，点「连接仓库」；已经连过仓库的话，点状态页项目概览右上角的「管理项目」，打开的是同一个页面。

  <img src="/images/zh/connect.png" alt="连接仓库页，显示「已用 0 / 上限 5 个仓库」、「仓库」和「基础分支（一般用默认）」两个下拉框，以及「连接仓库」按钮" />
</Frame>

1. 「仓库」：从你的 GitHub App 安装所覆盖的仓库里挑。仓库超过 8 个时会多一个「搜索仓库」框，输入名字的一部分就能筛选。
2. 「基础分支（一般用默认）」：Orbi 提交拉取请求的目标分支。选中一个仓库之后，页面会载入它真实的分支列表并预选默认分支，所以通常你只需要确认。列表里没有你要的分支，可以选「— 手动填写 —」自己填。
3. 点「连接仓库」。处理期间按钮会变成「正在连接…」，不用再点一次。

接着页面标题变成「仓库已连接」，并开始[准备工作环境](/zh/provisioning)。页面会自己更新，准备好之后会出现「写第一个需求」按钮，点它就到了[写需求](/zh/write-a-requirement)页。熟悉 GitHub 的话，也可以直接在仓库里新建 Issue 并打上 `ai-ready` 标签。

<Note>
如果仓库是空的，一个 commit 都没有，选中它时页面会提示你。连接时 Orbi 会在基础分支上放一个 README 文件作为第一个提交，因为 Orbi 需要有 commit 才能从它拉分支。
</Note>

想先试用的话，付费账户在还没到仓库上限时，下拉框下面有「想先试用？」一行，点「用 Orbi 的示例新建一个仓库」会在你的 GitHub 账号下新建一个示例仓库。一个能选的仓库都没有时，这个链接会变成页面上的主按钮。示例仓库也占一个仓库名额。

## 仓库要满足的条件

一个仓库只有满足下面几条才能被连接：

- 它**在你的 GitHub App 安装范围内**。Orbi 只看得见你授权过的仓库。
- 它**开启了 Issues**。Orbi 通过 Issues 接收任务，所以关掉了 Issues 的仓库在列表里会标上「（Issues 已关闭，需先开启）」，选中它时页面会给出「仓库设置」链接，连接时也会被拒掉。先到仓库的 Settings → Features 里勾选 Issues。
- 它**没有被归档**。归档的仓库不会出现在列表里。

已经连接的仓库也不会再出现在列表里。上面这些条件在你提交时都会重新检查，不只是在页面渲染时查一次，所以中间被取消授权的仓库也会被拦住。

## 列表里没有你的仓库时

列表里只有你的 App 安装覆盖到的仓库。如果你的不在里面，展开连接页上的「没找到你的仓库？」：

- 安装 App 时只选了部分仓库的话，点「GitHub App 设置」，在 Repository access 里把要连的仓库加进去，点 Save，再回来刷新。
- 仓库在组织下的话，在「安装页」选这个组织；你不是组织管理员的话，请管理员安装或批准。

如果 GitHub 的仓库列表完全读不出来，页面会写「无法从 GitHub 获取仓库列表，请稍后刷新，或在下面直接填写。」，并换成两个输入框：「仓库」里按「所有者/仓库名」格式直接填，「基础分支」默认是 `main`。这不会绕过授权检查：App 访问不到的仓库在提交时照样会被拒掉。

## 会卡住每一次合并的分支保护

如果你的基础分支要求合并前必须有人批准，连接成功页会立刻提醒你，因为这个设置会让**每一次**任务都停在合并那一步。

原因在身份：Orbi 用同一个 GitHub App 的身份提交拉取请求并合并它，而 GitHub 不允许拉取请求的作者批准自己的拉取请求。在必须批准的规则生效时，每个任务都只能走到检查通过、等着合并这一步，然后合不进去。这时状态页的标题是「需要你在 GitHub 上批准这次改动」，任务的状态显示「等你批准」。

提醒下面的「三种改法」里有三种解法，按你的策略挑一个：

1. **每次由人批准**。你或者同事在拉取请求上点 Approve，合并就继续。每一个改动都有人把关。
2. **允许管理员绕过**。在 GitHub 的 Settings → Branches → Branch protection rules（或者 Settings → Rules → Rulesets）下面勾选 Allow admins to bypass，或者把管理员账号加进 Ruleset 的 Bypass list。
3. **把审批要求降为 0**，在同一处设置里把 Required approvals 改成 0。

后两种要仓库管理员改设置。改完不需要重新连接，之后的任务就能正常合并。

## 连接多个仓库

如果你的套餐允许多个仓库，在状态页上点「管理项目」。连接页会显示你已用了多少、上限是多少（例如「已用 1 / 上限 5 个仓库」），并在「已连接仓库」下列出已连接的仓库。选另一个仓库，点「添加仓库」。新加的仓库不会影响已连接的那些，每个仓库有自己的工作环境，各自准备。

状态页上的项目概览标题是「项目 N / 上限 M」，每个项目一行，显示进行中、检查中、已完成的任务数。连了不止一个仓库时，点开一行就是这个项目的详情：基础分支、「现在的状态」、「任务记录」，以及「在 GitHub 上查看」和「去 GitHub 新建 Issue」两个按钮；付费账户还能看到当前版本和「版本」。

## 更换已连接的项目

所有套餐都是同一条规则：**先断开要换掉的仓库，再连接新的。** 连接新仓库不会自动替换旧的。

1. 点「管理项目」，在「已连接仓库」里找到要换掉的那个，点「断开」，再点「确认断开」。
2. 选新仓库，点「添加仓库」（一个都没连着时按钮是「连接仓库」）。

断开后 Orbi 会回收这个仓库的工作环境，不会改动 GitHub 上的仓库，历史记录和用量保留：它会出现在状态页「用量与设置」的「已断开的项目」里。以后再连接它，会重新准备工作环境，和任何新仓库一样需要几分钟。

如果已经到了套餐上限还去连接新仓库，页面会显示「已达到仓库数量上限」，并给出「去断开仓库」。Free 和 Solo 一次只能连一个仓库，页面上还会多一个升级到 Pro 的按钮，上面写着价格和仓库数。

## 各种报错是什么意思

| 页面上写的 | 发生了什么 | 怎么办 |
|---|---|---|
| Orbi 的 GitHub App 没有访问这个仓库的权限，所以连不上 | 仓库在你的安装范围之外 | 点页面上的「GitHub App 设置」，在 Repository access 里加上它，点 Save，再回来点「返回重试」 |
| 「无法连接仓库」：仓库关闭了 Issues，Orbi 收不到任务 | 仓库关掉了 Issues 功能 | 点「仓库设置」，在 Features 里勾选 Issues，再回来点「返回重试」 |
| 「已达到仓库数量上限」 | 连接的仓库数已经到了套餐上限 | 先断开一个；Free 和 Solo 也可以升级到 Pro |
| 「暂时无法校验仓库授权」 | 暂时没法向 GitHub 确认仓库授权，仓库还没连接 | 稍后点「返回重试」；一直失败就联系我们 |
| 无法从 GitHub 获取仓库列表 | GitHub 的 API 连不上 | 稍后刷新；也可以在下面的输入框里直接填写 |
| 仓库或分支名格式不对 | 手动填的值不是「所有者/仓库名」 | 按「所有者/仓库名」重填，例如 `orbi-build/orbi` |

## 接下来会发生什么

连接后 Orbi 会[准备工作环境](/zh/provisioning)：搭起任务运行的隔离环境，并把 `ai-*` 标签装进你的仓库。等「准备工作环境」这一步完成，就可以[写第一个需求](/zh/write-a-requirement)，或者[把已有的 Issue 交给 Orbi](/zh/first-issue)。
