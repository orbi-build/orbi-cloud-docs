你不需要配置模型 —— 订阅本身就含模型用量 —— 但如果你更愿意直接付钱给 provider，可以用自己的 key。

默认情况下，交付跑在 Orbi 的平台模型通道上，消耗你套餐里包含的 tokens。所以你可以一个 key 都不填就完成安装、连接仓库、走完一次交付。

配置自己的 key —— **BYOK**，bring your own key —— 会替换掉你这个租户的那条通道。你想指定某个模型、你所在组织要求流量走自己的 provider 账号、或者你不想被包含的月度额度卡住，这些情况就用它。

## 什么时候该配 key

| 情况 | 该做什么 |
|---|---|
| 你只想让它跑起来 | 什么都不用做，包含的额度会自动使用 |
| 你想用某个特定模型 | 用那个 provider 和模型配 BYOK |
| 你的合规要求必须走自己的 provider 账号 | 配 BYOK |
| 你已经用完月度 token 额度 | 配 BYOK —— BYOK 租户不受额度暂停的限制 |

## 怎么配

在状态页的 **模型配置**（Model configuration）卡片里，点 **配置自己的模型**。

<Frame caption="模型配置页面，包含 provider、base URL、model ID 和 API key 字段">
  <img src="/images/model-config.png" alt="模型配置页面，包含 provider、base URL、model ID 和 API key 字段" />
</Frame>

1. **Provider** —— 从列表里选。选中之后 base URL 会自动填好。
2. **baseUrl** —— 自动填好，可以改。只有在你用代理或私有网关时才需要改。
3. **model_id** —— 从该 provider 的已知模型里选，或者用 **手填其他模型** 输入列表里没有的 model ID。
4. **API key** —— 你在那个 provider 处的 key。

点 **保存模型配置**。

保存之后生效的是后续开始的交付。如果开通之前因为凭据不对失败过，保存一份改好的配置会自动重试。

## 你的 key 存在哪

你的 API key **静态加密存储**，回显给你时永远是掩码的 —— 页面显示的是类似 `••••1234` 的东西，从不显示 key 本身。它不会写进日志，不会进支持用的证据包，也不会出现在任何可能被分享出去的界面里。

<Frame caption="模型配置页面显示已保存的配置，key 是掩码的">
  <img src="/images/model-config-set.png" alt="模型配置页面显示已保存的配置，key 是掩码的" />
</Frame>

不要用邮件发你的 key，也不要粘进 GitHub Issue、pull request 或评论。就在这个页面上填 —— 这是你唯一需要的通道。

<Note>
列在这里的 provider，不等于承诺你的账号在它上面对某个模型有额度、有访问权限或者有足够的速率限制。如果你的 key 拿不到某个模型，交付会带着 provider 自己的报错失败。
</Note>

## 用列表里没有的 provider

随便选一个 provider 当起点，然后把 **baseUrl** 改成你网关的 URL，用 **手填其他模型** 输入 model ID。任何 OpenAI 兼容的端点都能用。你的配置按你填的原样存下来，回显时也不做改动。

## 移除你的 key

清空配置会让你的租户回到平台通道和包含的额度上。

## 用 BYOK 之后有什么变化

| | 平台通道（默认） | 你自己的 key |
|---|---|---|
| 谁付 token 的钱 | 套餐里包含 | 你付给你的 provider |
| 月度 token 额度 | 每月 300,000,000；到顶后交付暂停 | 不适用 —— 用量照样统计，但永不暂停 |
| 模型选择 | 由 Orbi 运维 | 你自己定 |
| 状态页上是否显示用量 | 是 | 是 |

额度怎么计，见[额度与限制](/zh/limits-and-quotas)。
