You don't have to write the Issue yourself. On the status page (the page you land on after signing in), click **Write a request** and say what you want changed in a sentence or two. Orbi reads the code in your project and writes a draft, usually in 3–5 minutes. When the draft is ready and Orbi has nothing to ask, it is handed to Orbi straight away and work starts. You only need to step in when Orbi asks you something or the pre-work check finds something missing.

## Start from a suggestion

**Review the draft first** on the status page opens a suggested draft that is already written. Read it, then **Hand off to Orbi**, or tell Orbi below what to change and review the revision first. Opening a suggestion does not create a GitHub Issue.

If the page says **You have another draft that hasn't been handed off:** with its title, **Open it** returns to that draft. Suggested drafts are kept separately from the request you wrote yourself.

## Write and hand off

1. On the status page, click **Write a request**. The button appears once a GitHub repository is [connected](/connect-repository). If you have connected several, use **Switch project** on the page to pick one.
2. Under **What would you like to change?**, describe it in plain words: a new feature, a bug fix, a text change. One sentence is enough; a longer description is fine too. Then click **Draft the request**.
3. Orbi reads your code and writes the draft. This usually takes 3–5 minutes and at most 20, and the page shows **Writing the draft** meanwhile. For a project you have only just connected, Orbi first waits for its work environment to be [prepared](/provisioning), usually another 10–20 seconds. You can close the page; to come back, click **Write a request** on the status page and then **Open draft**. Sometimes Orbi asks you a few questions, either along with the draft or before writing it; see the next section.
4. The draft states what you asked for, what your users should see when it is done, what is left out, and how Orbi read anything your words left open. When it has no questions and the pre-work check passes, Orbi hands it off by itself: this creates an Issue in your GitHub repository, and Orbi works from it. The page then shows **Handed off to Orbi** and **Usually starts within a minute**.
5. If the draft comes with questions, or the page says **The pre-work check still misses:**, read the draft and click **Hand off to Orbi** when it is right. This creates the Issue the same way.

If the page shows **Not started**, follow the steps the status page shows, or [contact us](/troubleshooting#getting-help). You do not need to hand it off again.

## Attach screenshots and files

In the request box you can paste, drop, or click **+ Attach files**. Orbi accepts images (png, jpg, gif, webp), HTML (html, htm) and text files (txt, md, csv, tsv, json, log): up to 10 files per draft, 10 MB each, and 50,000 characters of HTML and text together. A file that breaks a rule is not attached, and the page says why next to its name.

- Click an attached image to see it larger on the page.
- The page shows **Read N attachments** once Orbi has looked at them. If the [model you configured](/model-configuration) cannot take images, it says **Received N attachments; the current model cannot see images.** instead: the images were not shown to the model, so describe in words what matters in them.
- When the draft becomes several Issues, each one lists **Files on this issue**. Add a file to that Issue with **+** followed by the file name, or take it off with **Remove** followed by the file name.
- In the Issue Orbi creates, each image is a link to orbi.build that anyone with the link can open, and each HTML or text file is a collapsed block in the body. Do not attach secrets, tokens or personal data.
- A draft you never hand off is deleted after 30 days, with its files. Files already in a created Issue stay available.

## When Orbi isn't sure

If your request can be read more than one way, Orbi asks you rather than guessing. The questions and their options are listed under **Orbi chose these for you**, and Orbi has already picked the option it recommends for each. If the questions have no options, the card is titled **Orbi has a few questions** (**Answer them and Orbi starts.**): type your answers and click **Answer and start**. You can close the page meanwhile; when Orbi has questions it also emails you. With options, you will see one of two layouts:

- **A draft with questions under it.** The draft already uses the recommended answers, so if you agree you can hand it off without changing anything. If an answer isn't what you meant, pick another option, or choose **Other (write your own)** and type your own. Then click **Start with my changes**: Orbi rewrites the draft with your choices, which takes about a minute, and the hand-off then works as in the steps above. Changed your mind? Click **undo your changes**.
- **Questions with no draft yet.** Pick your answers the same way, then click **Start with these choices**.

To change anything else, write it in the box under the draft and click **Send**. Orbi rewrites the draft and keeps what you said before, so you don't have to repeat it.

## Add detail to an existing request

For an Issue at `ai-needs-detail`, click **Add the details** on the status page. **Add detail to a request** shows the original Issue number, **Orbi says it still needs these**, **What was written before**, and a **What to add** box. This page is tied to that Issue and has no project selector. When Orbi has already proposed a split or acceptance criteria for the Issue, the status page shows that proposal with a start button instead; see [troubleshooting](/troubleshooting#when-orbi-has-already-proposed-a-fix).

Write the missing detail and review the revised draft. Handing it off appends the confirmed detail to the original Issue, removes `ai-needs-detail` and adds `ai-ready`; it does not create another Issue. **Write another request** returns to the ordinary request page for a separate task.

## What gets created

When you hand off, Orbi creates a normal GitHub Issue in your connected repository. Its first line is `Submitted by @your-login via Orbi`, then a **View project status in Orbi** link, then the approved draft, word for word. On the status page it appears as a task, showing the Issue title.

The ordinary **Write a request** entry opens the project’s latest ordinary draft. Starting another request makes the new draft the one shown there. Suggested drafts have their own entry points. Unsubmitted drafts are kept for 7 days after their last change; Issues already handed off stay in GitHub.

## Usage

Try it free for 14 days; see [Limits and quotas](/limits-and-quotas) for the rules.

Writing drafts uses model tokens. Model sources are explained in [model configuration](/model-configuration); usage is counted as described in [limits and quotas](/limits-and-quotas).

## When to write the Issue yourself

If you already know exactly what you want and can list how to check it, [creating the Issue on GitHub](/first-issue) is quicker. Write a request helps most when you know what you want solved but not where to change the code.
