Orbi Cloud works out of the box — your subscription includes a shared model channel, and every delivery draws from your 300M token monthly quota with no configuration required. Bringing your own key (BYOK) is entirely optional. When you do configure a key, it replaces the platform channel for your tenant only; your own provider account is billed directly for token usage, and the monthly quota pause no longer applies to you.

## When to Configure Your Own Key

| Situation | What to Do |
|-----------|------------|
| You just want it to work | Nothing — the included quota is used automatically |
| You want a specific model | Configure BYOK with that provider and model |
| Your compliance requires your own provider account | Configure BYOK |
| You've hit the monthly token quota | Configure BYOK — BYOK tenants are not subject to the quota pause |

## Configure BYOK

From the status page, in the **Model configuration** card, click **Optional: configure your own model**.

<Frame caption="The model configuration page with provider, base URL, model ID and API key fields">
  <img src="/images/model-config.png" alt="The model configuration page with provider, base URL, model ID and API key fields" />
</Frame>

1. **Provider** — pick from the list. Selecting one fills in the base URL for you.
2. **baseUrl** — filled automatically, and editable. Change it only if you use a proxy or a private gateway.
3. **model_id** — choose from that provider's known models, or use **Enter another model** to type a model ID that is not in the list.
4. **API key** — your key from that provider.

Click **Save model configuration**.

<Note>
  Saving takes effect for deliveries that start afterwards — any delivery already in progress continues with whatever configuration it launched with. If provisioning previously failed because of a bad key, saving a corrected key retries provisioning automatically.
</Note>

## How Your Key Is Stored

Your API key is handled with the following protections from the moment you submit it:

- **Encrypted at rest** using AES-256-GCM — the plaintext key is never persisted to disk.
- **Shown back to you masked only** (for example, `••••1234`) — the full key is never displayed after entry.
- **Never written to logs** or included in support bundles exported from the platform.
- **Never shown in any interface** that could be screen-shared, copied, or forwarded.

<Frame caption="The model configuration page showing a saved configuration with the key masked">

<Warning>
  Do not paste your API key into a GitHub Issue, pull request, or comment. Enter it only on the model configuration page. Keys accidentally exposed in GitHub should be rotated immediately with your provider.
</Warning>

## Using an Unlisted Provider

Any OpenAI-compatible endpoint works with BYOK. To connect one:

1. Select any listed provider as a starting point to populate the base URL field.
2. Edit the base URL to point to your gateway's endpoint.
3. Use **Enter another model** to type the exact model ID your endpoint expects.

As long as the endpoint speaks the OpenAI chat completions API, Orbi Cloud can use it.

## Platform Channel vs. BYOK

| | Platform Channel (Default) | Your Own Key (BYOK) |
|---|---|---|
| **Who pays for tokens** | Included in your plan | You pay your provider directly |
| **Monthly token quota** | 300M/month; deliveries pause at the cap | Not applied — usage is measured but never paused |
| **Model choice** | Operated by Orbi | Yours — any provider and model you configure |
| **Usage shown on status page** | Yes | Yes |

## Removing Your Key

To return to the platform channel, clear your model configuration on the status page. Orbi Cloud immediately reverts to the included quota channel for all subsequent deliveries. Your previous BYOK usage history is retained for reference.
