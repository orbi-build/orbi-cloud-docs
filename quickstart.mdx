Sign in, install the GitHub App, and connect a repository. Orbi then reads it and suggests a first task for you to choose. You can also write a request or dispatch an existing Issue.

This is the shortest complete path. Every step ends with a **Success** check so you can tell whether to continue or to stop and fix something. The whole path happens in a browser and in GitHub. You never get a shell on the runner, and you never install anything locally.

**Before you start** you need a GitHub account and a repository you can install a GitHub App on (you must be its owner, or an organization owner/admin). The repository must have **Issues enabled**. Orbi reads and labels Issues, so a repository with Issues turned off cannot be connected.

<Tip>
You do not need a big or important repository to try it. Installing on a single small repository is enough to see the whole loop, and you can add others later.
</Tip>

## The page that guides you

**Setup progress** shows where you are: sign in, install the App, connect a repository, prepare the environment, write the first request, create a release, and subscription or the free allowance. Videos are available for **Install GitHub App**, **Connect repository**, and **Write your first request**. **Create Release** is optional; after the required steps and a delivery, the list folds into **All done**.

## 1. Sign in with GitHub

Open **[orbi.build/api/](https://orbi.build/api/)** and click **Sign in with GitHub**.

<Frame caption="The Orbi Cloud sign-in page, with the Sign in with GitHub button">
  <img src="/images/signin.png" alt="The Orbi Cloud sign-in page, with the Sign in with GitHub button" />
</Frame>

GitHub asks you to authorize Orbi Cloud. This step only establishes who you are; it does not give Orbi access to any repository yet.

<Note>
The page opens in Chinese if your browser prefers Chinese. Switch with 🇨🇳 ZH | 🇺🇸 EN in the top right of the sign-in page, or later from the account menu (your avatar, top right). The choice is remembered for a year.
</Note>

**Success:** you are signed in, with your GitHub avatar and login in the top right. If you have not installed the App yet, the page you land on is titled **Connect repository** and says **The Orbi GitHub App is not installed yet.** Otherwise it is the status page, titled **Orbi Cloud Status**.

## 2. Install the Orbi GitHub App

If you started from a button on orbi.build, GitHub may already have shown you the App installation screen. In that case skip ahead to step 3. Otherwise click **Install the Orbi GitHub App** on the page you landed on, and you are sent to GitHub.

On GitHub's installation screen, choose the account or organization that owns your repository, select **Only select repositories**, tick the repository you want Orbi to work in, and click **Install**.

The App needs write access to Issues, pull requests and repository contents to do its job: it labels Issues, opens pull requests and pushes the branch it works on. [Install the GitHub App](/install-app#what-the-permissions-are-for) explains every permission, and you can revoke the installation from GitHub at any time.

**Success:** GitHub returns you to Orbi. On first setup, if you authorized exactly one eligible repository, Orbi connects it on its default branch and opens the status page. With several repositories, you see **Connect repository**. If **Confirming the GitHub App installation** appears first, let it refresh; after a minute, use **Select repository**.

## 3. Connect the repository

Already connected and on the status page? Skip to step 4. If the selection form appears, follow the steps below.

Pick your repository from the **Repository** list (with more than 8 repositories, a **Search repositories** box appears above it; type part of the name to filter). Then check **Base branch (usually the default)**, the branch Orbi opens its pull requests against. Selecting a repository loads its real branches and preselects the default one, so usually you just confirm. Click **Connect repository**.

<Frame caption="The Connect repository page, with the Repository and Base branch (usually the default) lists">
  <img src="/images/connect.png" alt="The Connect repository page, with the Repository and Base branch (usually the default) lists and the Connect repository button" />
</Frame>

<Note>
A repository marked **(Issues disabled; enable them first)** has to have Issues enabled first, under the repository's Settings → Features. If your repository is missing from the list entirely, open **Cannot find your repository?** for the link to add it to the App installation.
</Note>

**Success:** connecting opens that project’s status page, where Orbi starts preparing the work environment.

## 4. Wait for the work environment

After you connect a repository, Orbi builds an isolated work environment for it and installs the delivery labels into the repository. **This usually takes 10–20 seconds**, and the page updates itself. You do not have to reload or do anything.

**Success:** **Prepare work environment** is marked **✓ Done**. Orbi then says it is reading the repository to pick things it can do right away, and shows recently read files. Suggestions usually take about 2 minutes; you can leave the page. Environment preparation and reading for suggestions are separate steps.

If preparation fails instead, the status page says so in the **Next** card, and **View failure reasons and repair steps** shows the reason and what to do. Most failures are platform-side and recover on their own. See [provisioning](/provisioning#when-provisioning-fails).

## 5. Give Orbi its first task

When suggestions are ready, the status page shows **Orbi suggests starting with these**:

- **New task:** click **Review draft** to read the draft already prepared for you. Tell Orbi what to change if needed, then click **Hand off to Orbi**. Opening the draft does not create an Issue; handing it off does.
- **Existing Issue:** click **Let Orbi do this** to apply `ai-ready` and dispatch it immediately.
- **Your own task:** use **Write a request**, pick another existing Issue shown on the page, or create an Issue on GitHub and add `ai-ready`.

Use **Get new suggestions** for another batch, or **Get suggestions** when none are available. You can write your own request at any point.

<Frame caption="Suggestions ready: review a new draft, or dispatch an existing Issue">
  <img src="/images/status-suggestions.png" alt="Suggestions ready: review a new draft, or dispatch an existing Issue" />
</Frame>

<Warning>
**The `ai-ready` label is what starts the work.** **Hand off to Orbi** and **Let Orbi do this** add it for you; if you write the Issue yourself on GitHub, add it yourself. An Issue without it is never picked up, however long it waits.
</Warning>

With the environment ready and quota available, a task normally starts within about a minute; queued work and version scope can make it wait. The regular pickup runs every five minutes.

**Success:** within a few minutes the label `ai-in-progress` appears on the Issue, the headline changes to **Orbi is coding**, and the task shows up under **In progress** in **Task history**.

<Frame caption="The status page with tasks: the project overview and the task history, with one stuck task in the Next card">
  <img src="/images/status-active.png" alt="The status page with a stuck task in the Next card, the project summary and the Task history below" />
</Frame>

From here Orbi writes the code, opens a pull request, checks it in a separate session and repairs what the check finds. The Issue reaches `ai-merged` once the checked commit is merged.

## While it runs

You do not have to wait silently. If you realise the Issue was missing something, **comment on the Issue**. The running session picks the correction up, usually within a minute. See [steering a delivery](/delivery-lifecycle#steering-a-delivery-that-is-already-running).

## What to do next

- Hand Orbi the next task. Queued tasks show up under **In progress** in **Task history** with the status **Queued**.
- When enough merged work has piled up to be worth a version, see [releases](/releases). Step 6 of **Setup progress**, **Create Release**, is optional.
- To understand each label and what moves between them, read [the delivery lifecycle](/delivery-lifecycle).
- If the Issue reaches `ai-blocked`, read [troubleshooting](/troubleshooting#ai-blocked). That state is waiting on a decision from you.
- Nothing happened after five minutes? Start at [troubleshooting](/troubleshooting#nothing-happens-after-i-label-an-issue).
