This page walks you through everything you need to do to get Orbi Cloud to deliver your first pull request: creating an account, granting repository access, connecting a repo, and labelling your first Issue. From sign-in to a merged PR, the process takes about five minutes of your time — the rest is Orbi working in the background.

<Steps>
  <Step title="Sign In with GitHub">
    Go to [orbi.build/api/](https://orbi.build/api/) and click **Sign in with GitHub**. GitHub will ask you to authorize the Orbi OAuth application.

    <Frame caption="The Orbi Cloud sign-in page, with the Sign in with GitHub button">
      <img src="/images/signin.png" alt="The Orbi Cloud sign-in page, with the Sign in with GitHub button" />
    </Frame>

    <Note>
      The OAuth grant requests only the `user:email` scope — Orbi cannot read or write your repositories at this stage. Repository access is granted separately through the GitHub App in the next step. Sessions remain active for 7 days before you need to sign in again.
    </Note>
  </Step>

  <Step title="Install the GitHub App">
    On the Orbi status page, click **Install GitHub App**. GitHub redirects you to the app installation screen where you grant Orbi access to your repositories.

    On that screen, select **Only select repositories** and choose the specific repository you want Orbi to manage, then click **Install**.

    <Tip>
      You can authorize multiple repositories during installation or add more later from your GitHub settings. However, Orbi connects and works on one repository at a time — you choose the active repository in the next step.
    </Tip>
  </Step>

  <Step title="Connect Your Repository">
    On the status page, click **Connect repository**. Select your repository from the dropdown and confirm the base branch — the branch Orbi will open pull requests against. Your repository's default branch is preselected, so usually you only need to confirm. Then click **Connect repository**.

    <Frame caption="The Connect repository page, with a repository dropdown and a base branch dropdown">
      <img src="/images/connect.png" alt="The Connect repository page, with a repository dropdown and a base branch dropdown" />
    </Frame>

    Provisioning starts automatically once you confirm. It typically completes in one to two minutes.

    <Warning>
      If your base branch has a branch protection rule that requires a minimum number of human approvals before merging, Orbi will not be able to merge pull requests automatically. Disable that requirement for the base branch, or approve each PR yourself. See [connect a repository](/connect-repository#branch-protection) for the three options.
    </Warning>
  </Step>

  <Step title="Wait for Provisioning">
    Watch the **Provisioning status** column in the **Connected repository** card on the status page. When it shows **Provisioned**, Orbi is ready. During provisioning, Orbi creates the `ai-ready`, `ai-in-progress`, `ai-pr-opened`, `ai-merged`, `ai-fix-needed`, and `ai-blocked` labels directly in your GitHub repository.

    <Note>
      If provisioning fails, the card tells you the reason and the next step. There are [four failure classes](/provisioning#when-provisioning-fails) — most platform-side failures recover automatically within a couple of minutes.
    </Note>
  </Step>

  <Step title="Label an Issue ai-ready">
    Create a GitHub Issue in your connected repository. Describe the single change you want made — what should change and how you'll know the change worked. Then apply the **`ai-ready`** label to the Issue. The label already exists; provisioning created it.

    Alternatively, open the status page and click **Let Orbi try this one** next to any existing open Issue to apply the label from the UI.

    <Frame caption="The status page listing untagged Issues, each with a Let Orbi try this one button">
      <img src="/images/status-ready-issues.png" alt="The status page listing untagged Issues, each with a Let Orbi try this one button" />
    </Frame>

    Orbi picks up labelled Issues within five minutes and begins delivery.
  </Step>
</Steps>

## What Happens Next

After you apply `ai-ready`, Orbi moves through a deterministic label sequence so you always know where your delivery stands. The label changes to `ai-in-progress` once Orbi starts implementing the change, then to `ai-pr-opened` when the pull request is created and routed to the independent review session. If the reviewer finds issues, the label briefly shows `ai-fix-needed` while Orbi applies repairs — this is a normal part of the cycle, not a failure. Once the review session approves the PR, Orbi merges it and the label updates to `ai-merged`.

You can follow every transition in real time on the [status page](/status-page) or directly in the GitHub Issue timeline.

## Tips for Your First Issue

- **Pick something small and specific.** A bug with a clear reproduction, a missing test, or a contained refactor finishes fast and shows you the whole loop.
- **Say what should change and how you'll know it worked.** "The export button produces a CSV with no header row; it should include one" gives Orbi more to work with than "fix export".
- **One Issue, one change.** Bundled Issues produce bundled PRs that are harder to review.
