Connecting a repository tells Orbi which repository's Issues it may work on, and which branch to open pull requests against.

Connecting is self-service: you pick the repository and the base branch on the connect page, and Orbi starts preparing the work environment right away. Connecting does not create any Issue in your repository. How many repositories can be connected at the same time depends on your plan: one on Free and Solo, up to five on Pro. Changing one always means disconnecting it first. See [limits and quotas](/limits-and-quotas).

## Connect

Before you have connected anything, the **Next** card on the status page says **Connect a GitHub repository first**; click **Connect repository**. Once you have a repository, click **Manage projects** in the top right of the project overview on the status page, which opens the same page.

  <img src="/images/connect.png" alt="The Connect repository page, showing Used 0 / limit 5 repositories, the Repository and Base branch (usually the default) lists, and the Connect repository button" />
</Frame>

1. **Repository**: pick from the repositories your GitHub App installation covers. With more than 8 repositories, a **Search repositories** box appears; type part of the name to filter the list.
2. **Base branch (usually the default)**: the branch Orbi opens pull requests against. Selecting a repository loads its real branches and preselects its default branch, so usually you just confirm. If the branch you want is not listed, choose **— Enter manually —** and type it.
3. Click **Connect repository**. The button changes to **Connecting…** while it works; you do not need to click again.

The page title then changes to **Repository connected** and Orbi starts [preparing the work environment](/provisioning). The page updates itself, and a **Write your first request** button appears when the environment is ready; it takes you to the [write a request](/write-a-requirement) page. If you know GitHub, you can also create an Issue in the repository directly and add the `ai-ready` label.

<Note>
If the repository is empty (no commits at all), the page tells you when you select it. When you connect, Orbi adds a README file as the first commit on the base branch, because Orbi needs a commit to branch from.
</Note>

If you want to try Orbi out first, paid accounts that are below their repository limit see a **Want to try it out first?** line under the list; **Create a repository from Orbi's example** creates an example repository under your GitHub account. When there is no repository you can select at all, that link becomes the page's main button. The example repository also uses one repository slot.

## Requirements a repository has to meet

A repository can only be connected if:

- It is **covered by your GitHub App installation**. Orbi only sees repositories you authorized.
- It has **Issues enabled**. Orbi receives tasks through Issues, so the list marks such a repository **(Issues disabled; enable them first)**, selecting it shows a link to the repository settings, and connecting it is rejected. Enable Issues under the repository's Settings → Features first.
- It is **not archived**. Archived repositories are left out of the list.

Repositories that are already connected are left out of the list too. These requirements are checked again when you submit, not just when the page renders, so a repository that was de-authorized in between is caught.

## When your repository is not listed

The list only contains repositories your App installation covers. If yours is missing, open **Cannot find your repository?** on the connect page:

- If you selected only some repositories when installing the App, follow the **GitHub App settings** link, add the repository under **Repository access**, click **Save**, then come back and refresh.
- If the repository belongs to an organization, choose that organization on the **installation page**; if you are not an organization administrator, ask an administrator to install or approve it.

If GitHub's repository listing cannot be read at all, the page says **Cannot retrieve the repository list from GitHub. Refresh later, or enter it below.** and switches to two text fields: type the repository as `owner/repository` under **Repository**, and **Base branch** defaults to `main`. This does not bypass the authorization check: a repository the App cannot access is still rejected on submit.

## Branch protection that blocks every merge

If your base branch requires approving reviews before merge, the page you land on after connecting warns you immediately, because this setting stops **every** task at the merge step.

The reason is identity: Orbi opens the pull request and merges it as the same GitHub App, and GitHub does not let a pull request's author approve their own pull request. With required approvals in force, each task gets as far as a checked, ready pull request and then cannot merge it. On the status page, the headline then reads **You need to approve this change on GitHub**, and the task's status shows **Awaiting approval**.

The warning's **Three ways to fix it** section lists the options. Pick whichever suits your policy:

1. **A person approves each change.** You or a colleague clicks **Approve** on the pull request, and the merge proceeds. Keeps a human in the loop on every change.
2. **Let admins bypass.** Under GitHub's Settings → Branches → Branch protection rules (or Settings → Rules → Rulesets), tick **Allow admins to bypass**, or add the administrator account to the ruleset's Bypass list.
3. **Set required approvals to 0** by changing **Required approvals** to 0 in the same setting.

The last two need a repository administrator to change settings. Changing it does not require reconnecting; later tasks merge normally.

## More than one repository

On a plan that allows several repositories, click **Manage projects** on the status page. The connect page shows how many you have used against your limit (for example **Used 1 / limit 5 repositories**) and lists the connected ones under **Connected repositories**; pick another repository and click **Add repository**. Adding one does not affect the repositories already connected, and each repository gets its own work environment, prepared separately.

On the status page, the project overview is headed **Project N / limit M** and has one row per project with its in-progress, under-review and done counts. With more than one repository connected, click a row to open that project's detail: its base branch, **Current status**, **Task history**, and the **View on GitHub** and **Create an Issue on GitHub** buttons; paid accounts also see the current version and **Versions**.

## Changing the connected repository

There is one rule on every plan: **disconnect the repository you are leaving, then connect the new one.** Connecting never replaces a repository on its own.

1. Click **Manage projects**. Under **Connected repositories**, click **Disconnect** on the repository you are leaving, then **Confirm disconnect**.
2. Pick the new repository and click **Add repository** (with nothing connected, the button reads **Connect repository**).

Disconnecting reclaims that repository's work environment. It does not change the repository on GitHub, and your history and usage are kept: the repository appears under **Disconnected projects** in **Usage and settings** on the status page. Connecting it again later prepares a fresh work environment, which takes a few minutes like any new repository.

If you try to connect a repository while you are already at your plan's limit, the page says **Repository limit reached** and offers **Disconnect a repository**. On Free and Solo, which connect one repository at a time, it also offers an upgrade-to-Pro button showing the price and repository count.

## What the errors mean

| What the page says | What happened | What to do |
|---|---|---|
| Orbi's GitHub App does not have access to the repository, so it cannot connect | The repository is outside your installation's scope | Follow **GitHub App settings** on the page, add the repository under **Repository access**, click **Save**, then come back and click **Back and retry** |
| **Cannot connect repository**: Issues are disabled in this repository, so Orbi cannot receive tasks | The repository has the Issues feature turned off | Follow the repository settings link, tick Issues under Features, then come back and click **Back and retry** |
| **Repository limit reached** | You already have as many repositories as your plan allows | Disconnect one first; on Free and Solo you can also upgrade to Pro |
| **Unable to verify repository authorization** | Orbi could not confirm the repository authorization with GitHub; the repository is not connected | Click **Back and retry** later; contact us if it keeps failing |
| Cannot retrieve the repository list from GitHub | GitHub's API could not be reached | Refresh later, or type the repository into the text fields below |
| The repository or branch name is not valid | The manually entered value is not `owner/repository` | Re-enter it as `owner/repository`, for example `orbi-build/orbi` |

## What happens next

After you connect, Orbi [prepares the work environment](/provisioning): it builds the isolated environment your tasks run in and installs the `ai-*` labels into your repository. When **Prepare work environment** is done, [write your first request](/write-a-requirement), or [hand Orbi one of your existing Issues](/first-issue).
