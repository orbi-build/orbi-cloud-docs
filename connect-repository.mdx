Connecting a repository tells Orbi which repo's Issues to act on and which branch to open pull requests against. Orbi works with one active repository at a time — you pick the repo, pick the base branch, and Orbi provisions itself automatically. Previous repository connections are retained in history and are never deleted.

## Requirements

Before connecting a repository, make sure it meets both of the following requirements:

- **Orbi GitHub App installed and authorized for the repository.** The repository must be within the scope of your Orbi GitHub App installation. If it is not, Orbi cannot read Issues or open pull requests on your behalf.
- **Issues enabled.** GitHub's Issues feature must be turned on for the repository. You can check this in the repository's **Settings → Features** section.

## Connect Your Repository

<Steps>
  <Step title="Open the connection screen">
    From the Orbi status page, click **Connect repository**.
  </Step>
  <Step title="Pick the repository">
    Select a repository from the dropdown. Only repositories already authorized in your Orbi GitHub App installation appear in this list.
  </Step>
  <Step title="Pick the base branch">
    Choose the branch you want Orbi to open pull requests against. Your repository's default branch is preselected.
  </Step>
  <Step title="Click Connect repository">
    Click **Connect repository** to confirm.
  </Step>
  <Step title="Wait for provisioning">
    You are returned to the status page and provisioning starts automatically. This typically takes **1–2 minutes**. The status page will update when the repository is ready for deliveries.
  </Step>
</Steps>

## Repository Not Listed?

The repository dropdown only shows repositories that are already authorized in your Orbi GitHub App installation. If you don't see the repo you want:

1. Click **Cannot find your repository?** below the dropdown.
2. Follow the link to your GitHub App configuration and add the repository.
3. Return to Orbi and reload — the repository will now appear in the dropdown.

If you know the repository's exact path, you can also use the **Enter manually** option and type it in `OWNER/REPO` format (for example, `acme-corp/backend`). Manually entered repositories are still validated against your App installation — Orbi will reject any repository that hasn't been authorized.

## Branch Protection

<Warning>
  If your base branch requires **approving reviews before merge**, every delivery will stall at the merge step. Orbi opens the pull request and merges it as the same GitHub App identity, and GitHub prevents a user from approving their own submission.

  Resolve this with one of three approaches:

  1. **Approve each PR yourself.** After Orbi's independent review passes and the PR is ready, add your own approving review to satisfy the branch protection rule.
  2. **Enable admin bypass.** In your branch protection settings, enable **Allow specified actors to bypass required pull request reviews** and add the Orbi App.
  3. **Set required approvals to 0.** Remove the approval requirement entirely for the base branch if your workflow doesn't depend on human sign-off.
</Warning>

## Changing the Connected Repository

The previously connected repository moves to **Historical Repositories** at the bottom of the status page. It is not deleted — its delivery history and configuration are preserved and remain readable.

<Note>
  You cannot change the connected repository while a delivery is in flight. Wait until the current delivery reaches `ai-merged` or `ai-blocked` before switching repositories.
</Note>

## Error Reference

If something goes wrong during the connection step, the status page will display one of the following messages.

| Message | Cause | Fix |
|---|---|---|
| Not authorized for the Orbi GitHub App | The repository is outside the scope of your App installation | Add the repository in GitHub → Settings → Applications → Installed GitHub Apps → Orbi → Configure, then reload |
| Issues are disabled | The Issues feature is turned off for this repository | Enable Issues in the repository's **Settings → Features** |
| A delivery is still in progress | A delivery is currently running on the active repository | Wait for the delivery to reach `ai-merged` or `ai-blocked`, then try again |
| Repository list unavailable | Orbi could not fetch the list of repositories from GitHub | Reload the page; if the problem persists, check your GitHub App installation is still active |
| Repository format is invalid | The manually entered value is not valid `OWNER/REPO` format | Re-enter the repository as `owner/repository` (for example, `acme-corp/backend`) |
