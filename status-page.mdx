The status page at **[orbi.build/api/](https://orbi.build/api/)** is where you see what Orbi is doing, what needs you, and what you have used.

The top of the page contains the account menu, title and What’s new. **Next** shows the current state and what needs you; while delivery is in progress, suggestions may appear in a separate **Orbi also suggested these** card. Project summaries and the folded **Usage and settings** follow.

With one project, its task history appears directly. With several projects, the overview does not combine task tables; open a project row to see its details. **Next** can be absent from a multi-project overview when there is nothing to act on.

## Next

The **Next** card shows setup progress, the current state and actions that need you. Once the environment is ready, the suggestion area moves from reading the repository to **Orbi suggests starting with these**. While reading, it shows recently read files and **About 2 minutes. You can leave this page**.

For a new task, **Review draft** opens the draft before you confirm. For an existing Issue, **Let Orbi do this** dispatches immediately. **Write a request** and the other existing Issues remain available. See [your first Issue](/first-issue).

<Frame caption="Suggestions ready, with Write a request and existing Issues still available">
  <img src="/images/status-suggestions.png" alt="Suggestions ready, with Write a request and existing Issues still available" />
</Frame>

With several projects, switch the suggestions between **All** and project buttons. **All** initially shows one suggestion per ready project; **Show N more** expands the others. Select a project before requesting a new batch.

### Headlines

| Headline | What it means |
|---|---|
| **Connect a repository first** | No repository is connected yet |
| **Orbi is preparing the work environment** | A newly connected repository's [work environment is being prepared](/provisioning); usually 10–20 seconds |
| **Work environment preparation failed; Orbi will retry automatically** | Preparation failed for a transient reason; Orbi retries on its own |
| **Work environment preparation failed (on Orbi's side)** | A platform-side failure; no action needed. See [preparing the work environment](/provisioning#when-provisioning-fails) |
| **Orbi is waiting for your first request** | Ready. Hand over an existing Issue with **Let Orbi do this**, or use **Write a request** |
| **Orbi is coding** | A task is being worked on |
| **A task is waiting for other tasks to finish first** | A task is queued behind the Issues it depends on |
| **A task has been waiting for over 10 minutes** | A task was handed to Orbi more than 10 minutes ago and has not been picked up |
| **A task is not in the current version and will not start yet** | A task is outside the current version, so Orbi will not start it for now (free accounts see **A task will not start yet**) |
| **Orbi is checking the change #N and merges it into your project when it passes** | The independent check is running |
| **You need to approve this change on GitHub** | Branch protection requires an approval before merge. See [branch protection](/connect-repository#branch-protection-that-blocks-every-merge) |
| **Orbi needs your confirmation** | A result is waiting for a human to confirm it |
| **Orbi is stuck and needs you** | A task is stuck, or something on your side needs fixing; the item under it says which |
| **Orbi is done. Waiting for your next request** | Everything is finished; Orbi is waiting for the next task |
| **Can't reach Orbi right now** | Orbi could not read your task state at the moment; the card offers **Refresh status page** or **Reconnect repository** |
| **Monthly AI usage is used up; new tasks are paused** | A paid account has used this month's AI usage; see below |

Two situations put their own way out in the items waiting on you:

- **Free runs used up**: the card has a **Subscribe** button. See [billing](/billing).
- **A paid account's monthly AI usage used up**: Orbi pauses new tasks, while tasks already running finish normally. The card offers **Use your own API key**, and on Solo also an upgrade to Pro; otherwise usage resets automatically on the 1st of next month at 8:00 Beijing time. See [limits and quotas](/limits-and-quotas#when-the-monthly-quota-runs-out).

### Setup progress

Seven steps track onboarding: **Sign in** → **Install GitHub App** → **Connect repository** → **Prepare work environment** → **Write your first request** → **Create Release** → **Subscribe**. A finished step is marked **Done**; the current one is highlighted, marked **Waiting for you**, **Orbi is working** or **Failed**. Only **Install GitHub App**, **Connect repository**, and **Write your first request** have a **How to do this step ▶** video link. If preparing the work environment fails, that step also shows how to contact us.

When it is the current step, step 6, **Create Release**, is marked **Optional**; skipping it does not affect Orbi's tasks. For accounts still on the free runs, the last step reads **First 3 free**, with a folded **Pricing and account** note. Once the required steps are done and you have had a delivery, the whole list folds into **All done**.

## Project overview

The **Project** / **Projects** section has one row per connected project, summarizing its current state. **Manage projects** shows the count and limit and opens the page for adding or disconnecting repositories.

With several projects, click a row for its base branch, current status, task history, versions, **View on GitHub** and **Create an Issue on GitHub**. Versions are available on Free too. Return to the overview to inspect another project.

## Task history

Your tasks, split across three tabs. Each task appears in exactly one of them:

| Tab | What is in it |
|---|---|
| **In progress** | Open tasks that have no pull request yet: queued, being coded, waiting for detail, or stuck before a pull request was opened |
| **Under review** | Open tasks that have a pull request: going through the independent check, being revised after it, waiting for your approval, or stuck after the pull request was opened |
| **Done** | Finished tasks: merged, or closed |

The columns are **Task**, **Status**, **Change** and **Updated**. The task links to the Issue on GitHub and the change links to its pull request. Once a task reports usage, a line under its title shows **Took**, **AI calls**, the token total (split into input, output and cache) and, if the run was interrupted, how many times it **Resumed**. A queued task also notes that it starts after the current one, or which Issues it is waiting on.

The status chips map to the `ai-*` labels described in [the delivery lifecycle](/delivery-lifecycle#what-each-label-means): **Queued**, **In progress**, **PR under review**, **Fix needed**, **Awaiting approval**, **Needs detail**, **Needs your confirmation**, **Blocked**, **Done**, **Closed**. Open the Issue to see the reason and the next step in Orbi's comment.

## Usage and settings

Folded by default: click **Usage and settings** to open it. It opens by itself when preparing the work environment failed, so the reason is in view.

<Frame caption="Usage and settings, opened: monthly AI usage, connected projects and versions">
  <img src="/images/status-settings.png" alt="Usage and settings, opened: monthly AI usage, connected projects and versions" />
</Frame>

**Monthly AI usage.** The **Monthly AI usage** line shows the tokens used this month and the **Cached** share. Paid accounts also see the plan's allowance, the **Used** percentage and **resets on the 1st at 8:00 Beijing time**, with a bar that turns amber at 80% and red at 100%. Free accounts use the one-time allowance of 3 merged deliveries rather than a monthly token allowance; this line shows their actual token usage. With your own API key configured, usage that ran on your key gets its own line, **Monthly AI usage (your API key)**. Cached tokens count toward the allowance the same as input and output tokens, so the cached share does not change how fast it is used. See [limits and quotas](/limits-and-quotas).

**Connected projects.** Each project with its **Base branch** and **Preparation status** (**Provisioned**, **Provisioning** or **Provisioning failed**); when preparation failed, it also shows **Reason:**, **Time:**, **Error ID:** and **Next:**. Projects you disconnected are listed in the folded **Disconnected projects** section.

<Frame caption="When preparing the work environment fails, Usage and settings opens with the reason, time, error ID and next step under Connected projects">
  <img src="/images/status-provision-failed.png" alt="When preparing the work environment fails, Usage and settings opens with the reason, time, error ID and next step under Connected projects" />
</Frame>

**Versions.** Available on every plan. Open it here for one project, or in that project’s detail view with several projects. You can inspect the current version, create and switch versions, and initiate a release task. This does not remove [free-delivery or plan limits](/limits-and-quotas). See [releases](/releases).

For accounts on the free runs, a **Founding-member offer** note can also appear here after the first merged delivery.

## The account menu and the footer

Subscription, **AI model settings**, language, support, these docs and **Sign out** are all in the account menu under your avatar. See [the account menu](/sign-in#the-account-menu).

The footer on every page has two lines. The first is **Need help?** followed by the **Telegram group**, **Report a bug (GitHub, public)** and support@orbi.build; the second links to **Status** (the service status page), **Privacy**, **Terms** and **GitHub**.

## Refreshing

The page updates itself during environment preparation and while reading for suggestions; you can leave it. Otherwise reload for the current state. Task status is read live from GitHub.

If Orbi cannot reach GitHub at the moment, the page says **Can't reach Orbi right now** rather than showing you a misleading empty list.
