The [status page](https://orbi.build/api/) shows deliveries in progress, items that need you, connected projects and usage. Open your avatar menu for account settings; it contains **AI model**, **Orbi message language** and **Notifications**.

You can also get here from GitHub: Orbi's task notices on an Issue (progress, started, PR opened, questions, blocked or recovered, review, hand-off, merged and release) include a **Project status: Open project status** line; replies that only confirm a command or your answer do not, and an Issue that Orbi Cloud creates for you has a **View project status in Orbi** link above the request (an Issue from **Write a request** opens with a `Submitted by @you via Orbi` line first). Either link opens that repository's project page.

## Next

The main card changes with the work. During setup it shows your current step. During a delivery it names the Issue and shows its three steps, **Writing code → Checking → Merging**, the latest reported activity and a folded **Latest progress**. The report describes what the session most recently said it was doing; the Issue labels and pull request determine the delivery result.

When something needs you, the main card shows the selected task’s reason and action. With several waiting items, use **N more need you** to move to another without leaving the page. The multi-project overview can also show the total number of items needing attention. Follow the action for the selected Issue: approve its PR, add detail or confirm Orbi’s proposal, correct a missing base branch, have Orbi file a fix ticket for a failing base branch, or read Orbi’s blocked comment. See [troubleshooting](/troubleshooting).

### Headlines

| Situation | What to do |
|---|---|
| Work environment is being prepared | Wait; usually 10–20 seconds. If it takes longer or fails, use the reason and help link on the page |
| Orbi is reading the repository | Wait for suggestions, usually about 2 minutes, or write your own request |
| Orbi is waiting for the first request | Review a suggestion, dispatch an existing Issue, or use **Write a request** |
| A delivery is running | Read its Issue and progress; another request queues behind it |
| A task needs detail | Use **Add the details** to update the original request |
| Orbi proposes a split or acceptance criteria | Check the proposal, **Edit** it if needed, then **Split it like this** or **Start with these**. See [troubleshooting](/troubleshooting#when-orbi-has-already-proposed-a-fix) |
| A change needs approval | Open its PR on GitHub and review it |
| A task is blocked | Read the explanation and repair the cause before [restarting it](/troubleshooting#ai-blocked) |
| A task is blocked because the base branch's own checks fail | **Have Orbi file the fix ticket**, or fix the base branch yourself. See [troubleshooting](/troubleshooting#checks-on-the-base-branch-itself-are-failing) |
| New tasks are paused because of usage limits | Follow [limits and quotas](/limits-and-quotas) |
| Task state cannot be read | Follow the refresh or sign-in instruction; an unreadable state is not an empty queue |

Suggestions can appear in the main card while a project is idle, or in a separate **Orbi also suggested these** card while work is running. **Let Orbi do this** hands a suggestion to Orbi straight away: an existing Issue gets `ai-ready`, and a new task is created as an Issue and started. **Review the draft first**, next to it, opens the draft so you can change it before handing it off. Suggestions Orbi expects to touch at most two files are labelled **About 10 minutes to a PR**. **Why this** expands the reason for a suggestion.

Try it free for 14 days; see [Limits and quotas](/limits-and-quotas) for the rules.

With several projects, use **All** or a project selector. **All** starts with one suggestion per ready project; expand the remaining suggestions to see more. Choose a project before requesting a new batch. See [your first Issue](/first-issue).

### Setup progress

There are **five** steps: **Sign in → Install GitHub App → Connect repository → Prepare work environment → Write your first request**. The last step is complete once you hand over the first task; it does not wait for a merge. Release creation and subscription are separate actions, not extra setup steps.

The installation, connection and first-request steps have short how-to videos. The environment step updates automatically while Orbi prepares it.

## Project overview

The **Project** / **Projects** area summarizes each connected project's current work, including the Issue number and title when work is running. **Manage projects** opens repository management and shows the used allowance and plan limit. An official example copy is listed separately and does not use a real-project slot.

With one project, its current state and task history appear directly. With several, open a project row for its base branch, current version, progress, task history and **Versions**. The multi-project overview does not merge every project's task table into one.

### README badge

A public project can show how many deliveries Orbi has merged in it, as a badge at the top of its README. Expand **README badge** on the project row to preview the badge and copy one line of Markdown; after the first merge, **View badge** highlights that entry. The status page offers it for public real projects, not private repositories or example copies.

The line looks like this, here for `orbi-build/orbi`:

```markdown
[![Orbi deliveries](https://orbi.build/proof/orbi-build/orbi/badge.svg)](https://orbi.build/proof/orbi-build/orbi?ref=badge-orbi)
```

[![Orbi deliveries](https://orbi.build/proof/orbi-build/orbi/badge.svg)](https://orbi.build/proof/orbi-build/orbi?ref=badge-orbi)

The number updates as Orbi delivers, with a cache of about an hour. Clicking the badge opens the project's [delivery records](/delivery-lifecycle#sharing-a-delivery). The same **README badge** entry is at the bottom of those records. If the repository stops being public or the Orbi GitHub App is uninstalled, the image shows just "Orbi" without a number instead of breaking.

To change the base branch, open **Manage projects → Change base branch**, choose an existing branch and save. See [connecting a repository](/connect-repository#changing-the-base-branch).

## Task history

For a single project, **Task history** is a list showing the Issue, status and update time. It starts with the three most recently updated tasks; **Show all (N)** expands the rest and **Hide** folds them again. Times use your browser's local time zone. The filter above the list shows **All**, **In progress**, **Queued**, **Needs your attention** or **Done**. **Needs your attention** holds blocked tasks (even with a PR open), tasks needing detail or your confirmation, and PRs awaiting your approval; a blocked task whose question you have already answered sits under **In progress** while Orbi picks it up.

In the selected-project details of a multi-project account, history still uses three tabs:

| Tab | What is in it |
|---|---|
| **In progress** | Open tasks queued or coding without a PR, plus tasks that are blocked or need detail or your confirmation, even with a PR open |
| **Under review** | Open tasks with a PR: checking, **Fix needed**, or waiting for approval |
| **Done** | Merged or closed tasks |

A queued task says what it is waiting for, including unresolved Issue dependencies. **View progress** selects that task's progress. When usage has been reported, the task also shows elapsed time, AI calls and tokens split into input, output and cache; an interrupted run can show its resume count. Usage that has not been reported is not counted as zero.

The [delivery lifecycle](/delivery-lifecycle#what-each-label-means) explains each status. Open the Issue for Orbi's explanation and the PR for the change. If the history cannot be read, that area says so; this does not mean there have been no tasks.

## Usage and settings

Open the folded **Usage and settings** area for monthly usage, connected-project preparation state and disconnected projects. A preparation failure opens it so you can see the reason, time, error ID and repair step.

**Monthly AI usage** shows platform tokens and the cached share. Where an allowance applies, it also shows the cap, used percentage and reset time: the 1st at 08:00 Beijing time (00:00 UTC). The meter turns amber at 80% and red at 100%. Usage on your key has a separate **Monthly AI usage (your API key)** line. Cached tokens count toward the allowance too. See [limits and quotas](/limits-and-quotas).

**Versions** is available on every plan: under **Usage and settings** for a single project, or in the selected project's details when there are several. It lets you create and switch versions and initiate a release task. See [releases](/releases).

## The account menu and the footer

Use **Settings** in the avatar menu for your model key, Orbi's message language and [Telegram notifications](/notifications). The menu also contains subscription, website-language, support, documentation and sign-out actions. Available items depend on the account and subscription.

The footer offers the Telegram support group, support email and a link to book 15 minutes with the founder, plus service status, privacy, terms and GitHub. A support chat window sits in the bottom-right corner of the page. Support links do not configure your bot notifications.

## On a phone

The same actions are available on a phone. Expand progress, task history and settings as needed; the selected task and its available action remain together.

## Refreshing

The page observes delivery state about every **15 seconds** while visible. It pauses observation in a hidden browser tab and refreshes when you return. Environment preparation and repository reading also update without a manual reload.

A permission error or rate limit pauses progress observation and offers **Refresh progress**. If sign-in expires, sign in again. A report that has stopped arriving is not proof of success or failure: inspect the Issue and PR for the current result.
