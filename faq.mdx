Quick answers to the questions that come up most often. Each answer links to the full explanation where relevant.

## Getting Started

<AccordionGroup>
  <Accordion title="Do I need to pay before trying it?">
    No. Sign-in, App installation, connecting a repository, provisioning, and your first 3 merged deliveries are all free. No card is required. See [Billing](/billing).
  </Accordion>

  <Accordion title="Do I need to configure a model or an API key?">
    No. A subscription includes 300M tokens/month and deliveries use the platform channel by default. Bring-your-own-key (BYOK) is optional — you can configure your own model provider if you prefer. See [Model Configuration](/model-configuration).
  </Accordion>

  <Accordion title="Do I have to install anything?">
    No. Everything happens in your browser and in GitHub. You never get a shell on the runner and nothing runs on your machine. The only installation step is adding the Orbi GitHub App to your GitHub account or organization.
  </Accordion>

  <Accordion title="Can I use it on a private repository?">
    Yes. The GitHub App works on private repositories you authorize. Orbi can only see repositories you explicitly include in the App installation.
  </Accordion>

  <Accordion title="Can I connect more than one repository?">
    Not at the same time — one active repository at a time. You can change which repository is connected at any time when no delivery is in flight. See [Connect a Repository](/connect-repository).
  </Accordion>

  <Accordion title="Does it work on an organization's repository?">
    Yes. Install the App on the organization rather than your personal account. That creates a separate tenant for the organization, with its own subscription and usage, independent of any personal tenant you may have.
  </Accordion>
</AccordionGroup>

## Running Deliveries

<AccordionGroup>
  <Accordion title="How do I give Orbi work?">
    Create an Issue in your connected repository and add the `ai-ready` label. Alternatively, use the **Let Orbi try this one** button on the status page. See [Your First Issue](/first-issue).
  </Accordion>

  <Accordion title="How long until it starts?">
    Up to 5 minutes. Issue pickup runs on a timer, not an event webhook, so there is a short delay between applying the label and Orbi beginning work.
  </Accordion>

  <Accordion title="How long does a delivery take?">
    It depends on the task. Small, well-specified Issues finish quickly. Large or vague Issues take longer and may require more repair rounds. Writing tight, specific Issues consistently produces faster results.
  </Accordion>

  <Accordion title="Can I change my mind while it's working?">
    Yes. Comment on the Issue with your correction or edit the Issue body. The session restarts and picks up your updated instructions. Orbi accepts up to 3 restarts per delivery; only trusted repository roles (maintainers and above) can steer a delivery in progress. See [Delivery Lifecycle](/delivery-lifecycle).
  </Accordion>

  <Accordion title="Can I stop a delivery?">
    Close the Issue. If the delivery was an unsubscribed delivery that never merged, closing it refunds that free-allowance slot so you can use it on another Issue.
  </Accordion>

  <Accordion title="Does Orbi review its own code?">
    The review runs in a separate session that did not write the code being reviewed. It is not the same session marking its own work. That said, your CI is what makes the guarantee concrete — the review session reads your check runs and uses them as evidence.
  </Accordion>

  <Accordion title="Does it merge without my approval?">
    Yes, when the independent review verdict is clean and the merge gate passes. If you want a human to approve every pull request before it merges, configure your branch protection to require an approving review. See [Security](/security#branch-protection).
  </Accordion>

  <Accordion title="What is `ai-blocked`?">
    A deliberate stop: automatic recovery wasn't safe, so a person must decide the next step. Read the comment Orbi left on the Issue for the reason, fix the underlying cause, then re-apply `ai-ready`. See [Troubleshooting](/troubleshooting#ai-blocked).
  </Accordion>
</AccordionGroup>

## Limits and Cost

<AccordionGroup>
  <Accordion title="What does it cost?">
    3 merged deliveries are free — no card required. After that, US$79/month includes 300M tokens and unlimited deliveries within that token budget. There is no overage charge; deliveries pause when you reach the cap. See [Billing](/billing).
  </Accordion>

  <Accordion title="Do failed deliveries use up my free allowance?">
    No. A delivery that ends `ai-blocked` or is closed without merging refunds its slot. Only successfully merged deliveries count against the free allowance.
  </Accordion>

  <Accordion title="How many deliveries does 300M tokens cover?">
    Roughly 85–400 merged deliveries per month, depending on task size and how well your model provider supports prompt caching. Smaller, well-specified Issues stay toward the higher end of that range.
  </Accordion>

  <Accordion title="What happens when I hit the monthly cap?">
    Newly labelled Issues have `ai-ready` removed automatically, with a comment explaining why. Deliveries already in flight are untouched and complete normally. Wait for the next billing period or switch to BYOK to continue. See [Limits and Quotas](/limits-and-quotas).
  </Accordion>

  <Accordion title="My quota is draining fast — why?">
    Check the **Monthly Cache Hit Rate** on the status page. Cache-miss tokens cost roughly 50× more than cache-hit tokens. A rate below 90% burns through your budget dramatically faster than expected. Large or vague Issues also cost more in both tokens and repair rounds.
  </Accordion>
</AccordionGroup>

## Releases

<AccordionGroup>
  <Accordion title="Does Orbi release automatically?">
    No, never. You cut a release manually by typing a version into the **Cut a release** form on the status page. Orbi executes the release process but does not decide when to release or what version to use. See [Releases](/releases).
  </Accordion>

  <Accordion title="Does it pick the version number?">
    No. You type it. The next version is a product decision Orbi won't make for you.
  </Accordion>

  <Accordion title="Why did my release stop at scope derivation?">
    Scope derivation expects a GitHub milestone whose title exactly matches the version you typed. Orbi does not create that milestone for you — create it in your repository before cutting the release.
  </Accordion>
</AccordionGroup>

## Security and Access

<AccordionGroup>
  <Accordion title="What can Orbi see?">
    Only the repositories in your GitHub App installation, and it works on one connected repository at a time. The OAuth sign-in uses `user:email` scope only — it establishes your identity and grants no repository access. See [Security](/security).
  </Accordion>

  <Accordion title="Where does my API key live?">
    Encrypted at rest with AES-256-GCM. Shown back to you masked only (for example, `••••1234`). Never written to logs, never included in support bundles, and never shown in any shareable interface.
  </Accordion>

  <Accordion title="How do I revoke access?">
    Uninstall the GitHub App from GitHub Settings → Applications → Installed GitHub Apps. Access ends immediately. Cancelling your subscription is a separate action — uninstalling the App does not cancel billing.
  </Accordion>

  <Accordion title="Can a platform upgrade interrupt my delivery?">
    No. Platform deployments cannot restart or cancel a delivery that is already executing. The same applies to quota guards — they only act on newly dispatched Issues, not deliveries in flight.
  </Accordion>
</AccordionGroup>

## Product

<AccordionGroup>
  <Accordion title="Is this the same as self-hosted Orbi?">
    Same delivery engine; the difference is who operates the runner. The engine is open source and self-hosting it is free — see [orbi.build](https://orbi.build). Orbi Cloud is the hosted version where Orbi operates the infrastructure for you.
  </Accordion>

  <Accordion title="Is it stable?">
    Orbi Cloud is in Private Beta. This documentation describes what currently ships. Features and limits may change, but there is no roadmap advertised here — only what exists today.
  </Accordion>

  <Accordion title="Where do I get help?">
    The Telegram group, linked from the **Technical Support** card on the status page. A QR code is included for joining on a phone. See [Troubleshooting](/troubleshooting#getting-help).
  </Accordion>
</AccordionGroup>
