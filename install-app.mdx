The Orbi GitHub App is how Orbi gets permission to read your issues, push branches, open pull requests, and merge them. You install the App once on your GitHub account or organization, then explicitly select which repositories it is allowed to access. Orbi only ever interacts with the repositories you authorize.

## Install the App

<Steps>
  <Step title="Open the installation flow">
    From the Orbi status page at [orbi.build/api/](https://orbi.build/api/), click **Install GitHub App**. If you have already started setup, follow the setup breadcrumb at the top of the page.
  </Step>
  <Step title="Choose an account or organization">
    GitHub's installation screen lists your personal account and any organizations where you have admin rights. Select the account you want Orbi to operate under.
  </Step>
  <Step title="Select Only select repositories">
    When prompted to choose repository access, select **Only select repositories**. This limits Orbi's reach to only the repos you explicitly pick — Orbi will never have access to your entire account.
  </Step>
  <Step title="Pick the repository">
    From the repository selector, choose the repository you want to connect to Orbi. You can authorize more repositories later without reinstalling the App.
  </Step>
  <Step title="Click Install & Authorize">
    Click **Install & Authorize**. GitHub installs the App and redirects you back to the Orbi status page.
  </Step>
</Steps>

## What the Permissions Are For

Orbi requests the minimum set of permissions needed to carry out the full delivery lifecycle — from reading an issue to merging the finished pull request. The table below explains each permission.

| Permission | Access | Why |
|---|---|---|
| Issues | Read and write | Read issue content; apply labels (`ai-in-progress`, `ai-pr-opened`, etc.); post status comments; set milestones |
| Pull requests | Read and write | Open the delivery PR, post review comments, and merge the PR after independent review passes |
| Contents | Read and write | Fetch the repository to begin work; push the delivery branch with the completed changes |
| Checks | Read-only | Read CI check results at each delivery gate before proceeding |
| Workflows | Read and write | Push or update files under `.github/workflows/` without being silently rejected by GitHub's workflow file protection |
| Variables | Read and write | Create and update the triage workflow variable used to synchronize delivery state |
| Administration | Read and write | Register a deploy key when setting up a new environment — used only during initial provisioning |

## Authorizing Additional Repositories

You can authorize multiple repositories under a single App installation. Only **one repository is active** in Orbi at a time, but pre-authorizing others means you can switch between them without returning to GitHub.

To add a repository to the App installation:

1. Go to **GitHub → Settings → Applications → Installed GitHub Apps**.
2. Find **Orbi** and click **Configure**.
3. Under **Repository access**, add the repository you want to authorize.
4. Click **Save**.

The new repository will appear in Orbi's repository dropdown the next time you connect or change repositories.

## Revoking Access

To remove Orbi's access to your account entirely:

1. Go to **GitHub → Settings → Applications → Installed GitHub Apps**.
2. Find **Orbi** and click **Configure**.
3. Scroll to the bottom and click **Uninstall**.

<Note>
  Uninstalling the GitHub App removes Orbi's repository access but does **not** cancel your subscription. Billing is managed separately. To cancel your subscription, use the billing controls on the Orbi status page before uninstalling.
</Note>

## Reinstalling the App

If you uninstall and later reinstall the Orbi GitHub App on the same GitHub account, Orbi reconnects to your existing tenant automatically. Your delivery history, repository connection, and model configuration are all preserved — reinstalling does not create a new tenant or reset your state.
